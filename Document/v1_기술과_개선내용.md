코드·커밋·개발 문서에서 확인한 사실만 정리했다. 선택 이유와 원인·결과는 추정하지 않았다. 기록이 없으면 “확인할 근거 없음”으로 표시했다. 코드 구현, 당시 문서의 실행 결과, 이번 분석의 확인 범위는 구분한다. 이번에는 Unity 실행·빌드·테스트·성능 측정을 하지 않았다.

## 프로젝트와 동작 흐름

초기 3D TPS RPG 브랜치다. README에는 스테이지의 몬스터 처치, 레벨 상승·스탯 성장, 조건 달성 후 포탈 이동을 설명한다.

플레이어 입력 → 플레이어 상태·적 Behavior Tree → 이동·공격 → 피해·사망·성장 → UI 출력 순서다. 저장 요청은 플레이어 스탯 → SavedData → JSON 파일로 이어진다. [S02·S03·S05]

v1 안에서 추가한 기능과 수정 이력을 정리했다. v2에서 바뀐 구조를 v1의 개선 성과로 포함하지 않았다.

## 사용 기술

| 기술 | 확인된 사용 |
| --- | --- |
| Unity·C# | Unity 2022.3.44f1, 게임 로직은 C#. |
| URP·Input System·Cinemachine | 패키지 버전은 각각 14.0.11·1.7.0·2.10.1. |
| Behavior Tree·NavMeshAgent | 적 탐지·이동·공격 평가와 경로 이동. |
| 플레이어 상태머신 | 자유 시점·타깃 시점·사망 상태. |
| Animator·벡터 내적 | 공격 동작과 정면 판정. |
| JSON·파일 저장·씬 이벤트 | 플레이어 데이터 저장·복원과 씬 완료 후 적용. |
| LinkedList | 감지한 타깃 목록 관리. |
| Shader·Shader Graph·라이트맵 | 림라이트·디졸브·노멀맵·조명 작업. |
| Unity IAP·Steamworks.NET | 테스트 상품 구매 요청과 SDK 생명주기. |

버전 설정 근거는 S01, 기술별 사용·선택 이유는 아래 항목의 근거에서 확인할 수 있다.

## 구현·개선 내용, 이유와 결과

### 1. 적의 탐지·이동·공격 구성

- 사용 기술: Behavior Tree, NavMeshAgent, Animator, 벡터 내적.
- 구현 내용: Selector·Sequence·Action 노드로 탐지·이동·공격을 구성했다. Zombie1은 거리·탐지 상태를 갱신한 뒤 트리를 평가한다.
- 흐름: 플레이어 위치 → 탐지·사거리·정면 확인 → 경로 이동 또는 공격 → 애니메이션·피해 반영.
- 선택 이유: v1 README에 적 행동 다양성을 위한 Behavior Tree 학습·구현, 공격 로직을 위한 벡터·내적·회전 학습이 명시되어 있다.
- 확인된 결과: 직접 구현한 노드와 좀비의 트리 구성을 코드로 확인했다. 행동 다양성이나 성능의 수치 비교는 확인할 근거 없음.
- 범위: 이것은 v1의 구현 내용이다. 적을 FSM으로 변경한 개선은 v2 문서에서 다룬다.
- 근거: S02.

### 2. 플레이어 입력과 상태 처리

- 사용 기술: Input System, 플레이어 상태머신, Cinemachine.
- 구현 내용: PlayerInputReader와 PlayerControls가 입력을 받고, 자유 시점·타깃 시점·사망 상태 코드가 있다.
- 흐름: 입력 → 현재 플레이어 상태 → 이동·공격·시점 처리.
- 선택 이유: v1에서 이 입력·카메라 기술을 선택한 이유는 확인할 근거 없음. v3의 선택 이유를 v1의 이유로 옮겨 적지 않았다.
- 확인된 결과: v1에도 플레이어 상태머신이 존재한다. “v1 전체가 Behavior Tree였다”는 설명은 코드와 다르다.
- 근거: S01·S02.

### 3. 저장과 씬 로딩 순서 변경

- 사용 기술: JSON, 코루틴, `SceneManager.sceneLoaded`.
- 문제: `134962ff`에 플레이어 로드를 기다리는 과정에서 무한 대기 문제가 계속된다는 작성자의 당시 기록이 있다. 원인 확정 기록은 아니다.
- 변경: `70f68122`는 씬 로드 이벤트 등록을 기록했다. `96e46204`는 AssetDatabase 방식에서 `JsonUtility`와 `persistentDataPath`로 저장 방식을 바꿨다고 명시했다.
- 최종 코드 흐름: 저장 데이터 보관 → 스테이지 이동 요청 → 씬 로드 완료 콜백 → 플레이어 스탯·UI 적용 → 이벤트 구독 해제.
- 결과: 저장·이어하기 코드가 확인된다. `70f68122`에는 EventSystem 충돌이 남았다고 적혀 있어 완전 해결 사례로 단정할 수 없다.
- 근거: S03, `134962ff`, `70f68122`, `96e46204`.

### 4. 타깃 목록을 List에서 LinkedList로 변경

- 사용 기술: LinkedList, Trigger 콜백, 사망 이벤트.
- 변경 내용: fd6078ca에서 List<Target>를 LinkedList<Target>로, 추가를 AddLast로, 첫 대상 선택을 First.Value로 바꿨다.
- 기록된 이유: 커밋에는 대상 삭제 비용을 줄이려는 의도가 적혀 있다.
- 흐름: 감지 범위 진입 → 목록 추가 → 대상 선택 → 범위 이탈·사망 시 Remove(target).
- 확인된 결과: 자료구조와 호출 변경은 확인했다. 코드에서 노드를 직접 보관해 제거한 변경이나 제거 시간 측정 자료는 확인하지 못했다.
- 한계: 커밋에 적힌 O(1) 의도를 달성된 성능 결과로 사용하지 않았다.
- 근거: S26, fd6078ca.

### 5. 최소 피해를 보장하는 피해 계산

- 사용 기술: 공통 DamageCalculator, 비율 감소·하한 처리.
- 구현 내용: 최종 피해는 max(공격력 × max(1 - 방어력 × 0.01, 0.2), 1)이다.
- 흐름: 공격자 공격력·피격자 방어력 → 감소 비율과 하한 계산 → ApplyDamage.
- 선택·수정 이유: v1에서 이 공식을 정한 구체적인 이유와 이전 공식의 장애 기록은 확인할 근거 없음.
- 확인된 결과: 분석한 v1 끝에는 이미 20% 비율 하한과 최소 피해 1이 있다. v2에서 최소 피해를 처음 도입했다고 설명할 수 없다.
- 근거: S05.

### 6. 림라이트·디졸브와 노멀맵 수정

- 사용 기술: Shader, Shader Graph, 라이트맵.
- 구현 내용: 림라이트·디졸브 소스와 라이트 베이크 커밋이 있다. shRimLight.shader는 법선·시선 내적 → 반전·거듭제곱 → Emission을 계산한다.
- 선택 이유: v1 README에 시각적 몰입감을 위한 제작·적용이라고 적혀 있다.
- 변경 내용: b3d53c25는 노멀맵 처리를 Lerp에서 다른 방식으로 수정했다고 기록했다.
- 확인된 결과: 셰이더 소스와 그래프 수정 이력이 있다. 구체적인 대체 연산의 선택 이유·수정 전후 화면 평가·렌더 성능 측정은 확인할 근거 없음.
- 근거: S23, b3d53c25, f8e9956a.

### 7. IAP와 Steam SDK 연동 시험

- 사용 기술: Unity IAP, Steamworks.NET.
- 구현 내용: IAPManager가 테스트 소모품 test1의 구매를 요청하고 결과 콜백을 받는다. SteamSDKManager는 초기화 → 콜백 실행 → 종료를 호출한다.
- 선택 이유: 관련 커밋에는 결제 테스트·SDK 연동 시도라고 기록되어 있다. 상용 서비스 적용 목적은 확인할 근거 없음.
- 확인된 결과: 연동 코드가 있다. 확인한 ProcessPurchase는 로그를 남기고 Complete를 반환하며, 상용 보상 지급·결제 운영 결과는 확인할 근거 없음.
- 근거: S04, 40be23fd, 20f0e9d3.

## 결과를 설명할 때 구분할 점

- JSON 저장과 최소 피해 보장은 이미 v1에 존재한다.
- 씬 로딩 수정 커밋에는 EventSystem 충돌이 남았다는 기록이 있다. 완전 해결로 표현하지 않는다.
- LinkedList 변경의 성능 개선량, 그래픽 품질 향상 수치, 상용 결제·Steam 출시 성과는 확인할 근거 없음.
- 초기 구현의 개인 기여 범위와 기록되지 않은 선택 동기는 추정하지 않았다.
