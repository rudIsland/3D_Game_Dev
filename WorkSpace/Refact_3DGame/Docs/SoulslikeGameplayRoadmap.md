# 소울류 전투·이동·카메라 통합 로드맵

## 1. 문서 목적과 적용 범위

이 문서는 현재 구현 수준에 맞춰 목표를 줄이는 계획이 아니다. 다음 플레이 경험을 먼저 고정하고, 현재 코드는 그 목표로 이동하기 위한 출발점으로만 평가한다.

- 거리, 방향, 선딜·타격·후딜에 책임이 따르는 무게 있는 근접 결투
- 입력은 즉시 수집하지만 행동 중 방향 전환과 취소는 구간별로 제한되는 조작
- 발 디딤, 무기 궤적, 실제 이동, 충돌과 피격 결과가 서로 모순되지 않는 화면
- 탐색, 인간형 락온과 NightShade 보스전에 맞게 변하면서 조작을 방해하지 않는 카메라
- 키보드·마우스 우선 검증
- 일반 인간형 적과 현재 크기 또는 약간 큰 NightShade를 첫 보스 기준으로 사용
- 초거대 보스와 게임패드는 기반이 안정된 뒤 별도 확장

이번 로드맵의 구현 문서는 다음 네 개다.

| 문서 | 책임 |
| --- | --- |
| `SoulslikeGameplayRoadmap.md` | 전체 순서, 영역 간 의존 관계, 공통 계약과 통합 완료 조건 |
| [SoulslikeCombatRoadmap.md](SoulslikeCombatRoadmap.md) | 행동 요청, 공격·방어·피격, 인간형 적과 NightShade 전투 |
| [SoulslikeCharacterMovementRoadmap.md](SoulslikeCharacterMovementRoadmap.md) | 지상·공중 이동, 회전, Root Motion, 충돌과 자세 보정 |
| [SoulslikeCameraRoadmap.md](SoulslikeCameraRoadmap.md) | 자유 시점, 소프트 보정, 락온, 충돌·가림과 전투 반응 |

[SoulslikeCombatRoadmap.md](SoulslikeCombatRoadmap.md)가 행동 계약뿐 아니라 접촉 데이터, 타격 Queue, 순수 결과 계산, Unit 반영과 방어 표면의 상세 계약까지 소유한다. 날짜가 붙은 기존 로드맵과 구현 로그는 과거 결정과 구현 근거를 확인하는 기록으로만 사용하며 현재 계약의 별도 우선순위를 만들지 않는다.

## 2. 공통 플레이 계약

### 2.1 입력 → 처리 → 출력

```text
키보드·마우스 입력
→ 장치와 무관한 행동 요청으로 변환
→ 만료 시간과 한 번만 소비되는 요청 버퍼에 기록
→ 현재 행동 구간, 우선순위, 자원과 충돌 조건 검사
→ 허용되는 첫 프레임에 행동 시작
→ 이동 의도·Root Motion·피격 이동을 캐릭터 모터에 제출
→ 캐릭터 모터가 지면·경사·계단·벽·단차 충돌을 적용해 최종 이동 확정
→ 무기 궤적과 방어 표면을 검사해 공통 타격 결과 계산
→ Animator·IK·VFX·Audio·카메라가 확정된 결과를 표현
```

입력 수집은 행동 실행과 분리한다. 입력을 받았다는 이유로 즉시 상태를 바꾸지 않으며, 상태가 요청을 허용하는 첫 프레임에 정확히 한 번 소비한다. 버퍼 시간과 취소 시점은 임의의 공통 상수가 아니라 애니메이션 측정값과 PlayMode 결과로 행동별 확정한다.

### 2.2 행동 구간

모든 일회성 행동은 최소한 다음 구간을 가진다.

| 구간 | 의미 | 방향·이동 | 요청 처리 |
| --- | --- | --- | --- |
| 준비 | 행동을 읽을 수 있는 선딜 | 공격 설정이 허용한 제한 각도 안에서만 보정 | 더 높은 우선순위 중단만 즉시 처리 |
| 실제 작동 | 공격 판정, 회피 무적, 패리 판정처럼 결과가 발생하는 구간 | 방향과 이동을 강하게 고정 | 일반 취소 금지 |
| 회복 | 결과 이후 책임이 남는 후딜 | 초반 고정, 후반에만 제한 완화 | 설정된 후반부터 다음 요청 소비 |

가드는 지속 행동이므로 `진입 → 유지 → 해제 또는 Guard Break`를 사용하지만, 진입·패리·해제에는 같은 요청 및 우선순위 규칙을 적용한다. 상태 이름이나 Animator normalized time만으로 게임 규칙을 추측하지 않고, 행동 데이터 또는 명시적 이벤트가 구간 전환을 알린다.

### 2.3 전환 우선순위

동시에 여러 결과와 요청이 도착하면 다음 우선순위를 사용한다.

1. 사망
2. Knockdown, Guard Break, Parried
3. 강한 피격과 강제 경직
4. 공격, 회피, 가드, 점프 같은 의도적 행동
5. 일반 이동

같은 4순위 안에서는 현재 행동의 취소 표, 요청 시각과 자원 조건으로 결정한다. 한 프레임에 두 행동을 시작하지 않으며, 소비되지 않은 낮은 우선순위 요청은 아직 유효할 때만 버퍼에 남긴다. `Damaged`처럼 상태를 끊지 않는 결과와 `Staggered`처럼 끊는 결과는 [SoulslikeCombatRoadmap.md](SoulslikeCombatRoadmap.md)의 공통 타격 결과 의미를 따른다.

### 2.4 중단·실패·충돌 규칙

- 요청이 만료되거나 자원·지면·상태 조건을 만족하지 못하면 실행하지 않는다. 실패가 입력을 영구 보관하지 않게 한다.
- 행동이 더 높은 우선순위 결과로 중단되면 공격 판정, 무적, 패리, Root Motion 잔여량과 이벤트 구독을 즉시 정리한다.
- 공격 중 무기 또는 전진 경로가 벽에 막히면 해당 프레임 이후의 공격 이동과 타격을 끝내고 벽 반동 결과로 전환한다.
- 충돌 때문에 적용하지 못한 Root Motion은 다음 프레임에 누적하지 않는다.
- Hit Stop은 공격자와 피해자의 행동 표현을 제한하지만 카메라 입력, 카메라 충돌 복구와 요청 만료 정책은 명시적으로 계속 갱신한다.
- Disable·사망·씬 전환에서는 버퍼, 락온, 공격 판정, 방어 표면, 무적과 카메라 반응을 한곳에서 정리한다.

## 3. 책임 경계와 데이터 소유자

| 책임 | 소유자 | 소유하지 않는 것 |
| --- | --- | --- |
| 물리 입력 수집 | 입력 경계 | 행동 실행 여부와 Animator 상태 |
| 행동 요청과 만료 | 고정 크기 요청 버퍼 | 이동 충돌과 타격 결과 |
| 행동 전환과 구간 | 행동 상태 머신 | 지면 해결과 카메라 구도 |
| 행동별 거리·각도·구간·자원 값 | 행동 설정 데이터 | 현재 런타임 상태 |
| 이동 소스 조합과 최종 충돌 | 캐릭터 모터 | 공격 피해 계산과 IK |
| 무기 궤적·방어 표면 접촉 | 전투 감지 경계 | 체력·Stamina 직접 변경 |
| 타격 결과 계산과 Unit 반영 | 공통 전투·Unit 계층 | VFX·Audio·카메라 자산 선택 |
| 적의 거리·각도·재사용 판단 | 적 전투 의사결정 | 전용 타격 결과 의미 |
| 카메라 후보 점수와 문맥 | 카메라 계층 | 플레이어 행동 상태 변경 |
| Animator·IK·VFX·Audio | 표현 계층 | 충돌 위치와 성공 여부 재판정 |

`MonoBehaviour`는 Inspector 연결, Unity 이벤트, 물리 질의, Animator와 Cinemachine 같은 Unity 경계 역할을 우선한다. 요청 버퍼, 우선순위, 후보 점수, 공격 선택과 결과 계산은 가능한 한 일반 C# 클래스로 두고 `Create/Enable/Update/Disable/Destroy` 또는 `Dispose` 호출 순서를 Controller 한곳에서 확인할 수 있게 한다.

반복 구간은 고정 크기 버퍼와 캐시를 사용한다. `Update`, 무기 검색과 카메라 후보 검색에서 LINQ, 매 프레임 배열·문자열 생성, 클로저와 반복 `GetComponent`를 피하되, 측정 근거 없이 복잡한 풀이나 범용 util 계층을 추가하지 않는다.

## 4. 영역 의존 관계

```text
행동 계약과 측정 기준
├─ 캐릭터 모터 ─ 자유 이동 ─ Root Motion 충돌 ─ 점프·착지
├─ 자유 카메라 충돌 ─ 소프트 보정 ─ 락온·스트레이프 ─ 보스 카메라
└─ 한손검·방패 구간 ─ 무기 궤적·벽 반동 ─ 방어 결과
                                      └─ 인간형 적 ─ 무기 확장 ─ NightShade

이동·전투·카메라 공통 결과
└─ Hit Stop·VFX·Audio·카메라 반응·IK ─ 성능 및 좁은 공간 회귀
```

의존 관계의 핵심은 다음과 같다.

- 락온 스트레이프는 카메라보다 캐릭터 모터를 새로 만들지 않는다. 자유 이동과 같은 지면·충돌 계산을 사용한다.
- 공격 Root Motion과 피격 이동은 캐릭터 모터가 안정된 뒤 연결한다.
- 카메라 소프트 보정과 락온 후보는 같은 후보 수집 기반을 공유하지만 자동 보정과 수동 락온 상태는 분리한다.
- NightShade는 공통 공격·방어·타격 결과와 인간형 락온이 검증된 뒤 통합한다.
- 연출과 절차적 자세 보정은 판정과 이동 결과가 확정된 뒤 추가한다.

## 5. 현재 구현 기준선과 새 진행 상태

새 완료 기준으로 재검증하기 전에는 과거 구현이 있어도 해당 단계를 완료로 표시하지 않는다.

| 영역 | 보존할 현재 기반 | 목표 대비 부족한 점 | 새 진행 상태 |
| --- | --- | --- | --- |
| 이동 | `CharacterController`, 카메라 기준 자유 이동, 락온 스트레이프, 공격·구르기·가드 Root Motion, 피격 밀림 | 이동 소스가 하나의 최종 모터 제출 경로로 모이지 않음, 점프·낙하·착지 없음, 벽에 막힌 Root Motion 잔여 규칙과 경사·계단 회귀 근거 부족 | 기준선 재측정 필요 |
| 전투 | 행동 상태, 5연속 공격과 달리기 공격, 공격 입력 버퍼, 구르기·가드, 이동 구간 Sweep을 포함한 무기 판정, 공통 Hit/Stamina/Stagger/Super Armor 데이터 | 행동 전체 버퍼·우선순위·취소 표가 없음, 벽 반동과 무기 구간별 접촉 의미 부족, Player·NightShade의 공통 공격 구간 통합과 PlayMode 근거 부족 | 기준선 재측정 필요 |
| 카메라 | Cinemachine FreeLook/TargetLook, 축 연속성 보존, 거리·전방 각도 기반 NonAlloc 후보 검색, 락온 스트레이프 | 화면 중심·가시성·공격 의도 점수, 지속 가림·화면 이탈 해제, 단계적 충돌 복구, NightShade 문맥과 반응 중첩 상한 부족 | 기준선 재측정 필요 |
| NightShade | 13개 공격 ID, 거리·각도·가중치·쿨다운·페이즈·최근 공격·연계·준비 회전·회복 데이터 | 창 끝·중간·손잡이 접촉과 벽 충돌, 제한된 분기 시점 계약, 공통 행동 우선순위와 보스 카메라의 통합 검증 부족 | 기반만 존재 |

## 6. 측정과 완료 판정 원칙

### 6.1 먼저 측정할 값

각 공격, 회피와 피격 애니메이션마다 다음을 기록한다.

- 원본 클립 길이와 실제 재생 속도
- 양발 접촉·이탈 프레임과 발 미끄러짐 구간
- 누적 Root Motion 거리·회전과 프레임별 최대 이동량
- 무기 활성 시작·종료, 가장 빠른 접촉과 가장 늦은 접촉 프레임
- 준비·실제 작동·회복 경계와 각 구간의 허용 회전 각도
- 다음 행동 버퍼를 열 수 있는 프레임과 취소 가능한 결과
- 카메라 거리·FOV·피벗 변화가 전투 가독성을 해치기 시작하는 범위

측정값은 초깃값을 정하는 근거다. 최종값은 30·60·120 FPS PlayMode 비교와 실제 조작 결과로 확정한다.

### 6.2 공통 테스트 공간

전용 테스트 공간에는 평지, 오르막·내리막, 경사 경계, 낮고 높은 계단, 벽, 문, 기둥, 낮은 천장, 좁은 통로, 낙하 가능한 단차와 카메라를 가리는 얇고 두꺼운 장애물을 둔다. 동일한 시작 위치와 입력 재생으로 다음 결과를 비교할 수 있어야 한다.

- 이동·회피·공격별 최종 거리와 회전
- 벽 접촉 시 정지 위치와 남은 Root Motion 처리
- 한 공격에서 대상별 타격 횟수와 접촉 부위
- 락온 선택·유지·해제와 카메라 최대 각속도
- 반복 구간의 CPU 시간, 물리 질의 수와 `GC Alloc`

### 6.3 단계 완료 증거

모든 단계는 다음 세 종류를 모두 기록해야 완료다.

1. 자동 테스트: 순수 규칙, 경계값, 한 번만 소비, 프레임 독립성을 검증한다.
2. Unity PlayMode: 키보드·마우스로 조작하고 Scene, Animator 상태·파라미터와 충돌 결과를 확인한다.
3. Profiler: 정상 이동, 카메라 후보·충돌 복구, 타격 검색 반복 구간의 관리 힙 `GC Alloc 0 B` 목표와 물리 질의 수를 기록한다.

빌드나 자동 테스트만 성공한 단계는 `부분 확인`으로 남긴다. Unity Editor가 열려 있어 batchmode를 실행할 수 없으면 열린 Editor의 Test Runner와 PlayMode로 검증하며, 실행하지 못한 항목은 `미확인`으로 적는다.

## 7. 통합 마일스톤

모든 마일스톤은 아래 1~7 항목 순서로 기록한다.

### 마일스톤 1. 목표 계약, 측정 항목과 전투 테스트 공간

1. **목표 동작 정의:** 행동 구간, 우선순위, 이동 소스, 카메라 문맥과 완료 지표를 수치화할 수 있는 기준선을 만든다.
2. **입력 → 처리 → 출력:** 측정용 입력 시나리오 → 클립·Root Motion·충돌·카메라 값 기록 → 비교 가능한 기준선 표와 테스트 공간 출력.
3. **책임 경계와 데이터 소유자:** 통합 문서는 공통 계약을, 각 영역 문서는 세부 지표를, 테스트 Scene은 재현 가능한 배치만 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 측정 장치가 없거나 재현 입력이 불안정하면 값 확정을 중단하고 `미측정`으로 남긴다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 CharacterTest 환경과 구현 로그를 참고하되 새 지형·프레임·Profiler 기준을 추가한다.
6. **작은 단위의 점진적 전환 순서:** 자산 목록 작성 → 클립 측정 → 지형 모듈 배치 → 입력 시나리오 → 기준선 기록.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 측정표, 30·60·120 FPS 실행 방법, 테스트 공간 체크리스트와 Profiler 기준선이 재현된다.

### 마일스톤 2. 지면·경사·계단·벽을 처리하는 캐릭터 모터

1. **목표 동작 정의:** 모든 행동이 하나의 운동학적 충돌 몸체와 최종 이동 경로를 사용한다.
2. **입력 → 처리 → 출력:** 이동 소스별 요청 → 우선순위 조합과 지면·벽 해결 → 한 번의 최종 이동과 충돌 결과.
3. **책임 경계와 데이터 소유자:** 모터는 충돌과 최종 변위만, 행동과 Animator는 이동 의도만 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 막힌 성분은 폐기하고 다음 프레임으로 누적하지 않으며 접지 상실을 명시적 공중 상태에 전달한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 `CharacterController`와 이동 모드를 유지하면서 분산된 `Move` 경로를 작은 단계로 모은다.
6. **작은 단위의 점진적 전환 순서:** 일반 이동 → 중력 → 피격 이동 → Root Motion 순서로 제출 경계를 통합한다.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 전용 지형과 30·60·120 FPS에서 관통·떨림·잔여 이동 없이 동일한 허용 오차 안의 결과를 낸다.

### 마일스톤 3. 키보드·마우스 자유 이동과 자유 시점 충돌 카메라

1. **목표 동작 정의:** WASD 이동과 마우스 시점이 즉각적이며 벽·기둥·낮은 천장에서 카메라가 튀거나 관통하지 않는다.
2. **입력 → 처리 → 출력:** 이동·마우스 입력 → 카메라 기준 이동과 체적 충돌 카메라 계산 → 캐릭터 이동과 안정된 화면.
3. **책임 경계와 데이터 소유자:** 이동 모터는 캐릭터, 카메라 리그는 구도와 충돌 복구를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 카메라 공간이 부족하면 거리 축소 후 피벗을 보정하고, 장애물 제거 뒤에는 제한 속도로 복귀한다.
5. **현재 구현에서 보존할 점과 부족한 점:** FreeLook 입력과 Cinemachine 기반을 유지하며 체적 검사와 복귀 규칙을 측정한다.
6. **작은 단위의 점진적 전환 순서:** 평지 구도 → 벽 거리 축소 → 피벗 보정 → 낮은 천장 → 복귀 감쇠.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 좁은 공간 PlayMode와 Profiler에서 급회전·클리핑 없이 카메라 반복 구간 `GC Alloc 0 B`를 목표로 한다.

### 마일스톤 4. 소프트 타겟 보정, 수동 락온과 스트레이프

1. **목표 동작 정의:** 자유 공격은 제한 각도만 보정하고, 수동 락온은 대상 중심 스트레이프를 제공하되 카메라 입력을 빼앗지 않는다.
2. **입력 → 처리 → 출력:** 공격 의도 또는 락온 입력 → 거리·화면 각도·가시성 후보 점수 → 제한 회전 또는 명시적 TargetLook.
3. **책임 경계와 데이터 소유자:** 후보 서비스는 점수와 대상만, 전투는 공격 보정, 카메라는 구도, 이동은 스트레이프를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 후보가 없으면 소프트 보정 없이 공격하고, 락온 해제 시 현재 축에서 FreeLook으로 이어진다.
5. **현재 구현에서 보존할 점과 부족한 점:** NonAlloc 검색과 FreeLook/TargetLook 축 복사를 유지하고 가시성·화면 중심 점수를 추가한다.
6. **작은 단위의 점진적 전환 순서:** 후보 점수 테스트 → 소프트 보정 → 락온 선택 → 스트레이프 → 해제와 재선택.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 단일·복수 대상 PlayMode에서 예측 가능한 선택과 해제, 제한 각도, 프레임별 동일 후보를 확인한다.

### 마일스톤 5. 한손검·방패 공격 단계, 입력 버퍼와 Root Motion 충돌

1. **목표 동작 정의:** 한손검·방패로 준비·실제 타격·회복, 행동 버퍼와 구간별 취소를 완성한다.
2. **입력 → 처리 → 출력:** 공격·회피·가드 요청 → 우선순위·자원·행동 구간 판단 → 충돌이 적용된 Root Motion과 Animator 출력.
3. **책임 경계와 데이터 소유자:** 행동 상태는 전환, 행동 설정은 구간과 허용값, 모터는 이동 충돌을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 실제 타격 구간은 일반 취소를 막고, 회복 후반에만 유효 요청을 한 번 소비한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 콤보 버퍼와 공격별 이동 스케일을 보존하며 모든 행동 요청으로 계약을 넓힌다.
6. **작은 단위의 점진적 전환 순서:** 단일 공격 → 연속 공격 → 회피 요청 → 가드 요청 → 벽에서 Root Motion 정지.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 요청이 허용 첫 프레임에 한 번 실행되고 공격 이동이 벽을 관통하거나 누적되지 않는다.

### 마일스톤 6. 무기 궤적, 벽 반동과 타격 결과

1. **목표 동작 정의:** 프레임이 낮아도 검 궤적을 놓치지 않고 벽과 Unit 접촉을 구분해 일관된 결과를 낸다.
2. **입력 → 처리 → 출력:** 이전·현재 무기 형상과 공격 설정 → Sweep·중복 제거·벽 우선 규칙 → 타격 결과 또는 벽 반동.
3. **책임 경계와 데이터 소유자:** 감지기는 접촉, 계산기는 결과, Unit은 상태 반영, 표현은 반동 애니메이션과 효과를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 벽 접촉 뒤 공격 이동과 Unit 타격을 닫고 같은 활성 주기에서 재개하지 않는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 Overlap·Sweep·대상별 중복 제거를 유지하고 환경 충돌 계약을 추가한다.
6. **작은 단위의 점진적 전환 순서:** 검 형상 측정 → Sweep 회귀 → 환경 레이어 → 벽 반동 → 결과 표현.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 30·60·120 FPS에서 대상별 타격 횟수와 벽 반동 시점이 같고 좁은 벽에서 관통하지 않는다.

### 마일스톤 7. 회피·가드·패리·Stamina·경직·강인도

1. **목표 동작 정의:** 방향과 타이밍에 책임이 있는 방어와 공격 강도에 맞는 피격 중단을 제공한다.
2. **입력 → 처리 → 출력:** 방어 요청·접촉·공격 설정 → 무적·가드 표면·패리·Stamina·강인도 계산 → 공통 결과와 반응.
3. **책임 경계와 데이터 소유자:** 공통 타격 계산은 결과 의미를, 행동 상태는 방어 창을, Unit은 자원과 누적값을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** Stamina 부족은 Guard Break, 패리 성공은 공격자 Parried, 슈퍼아머는 피해는 받되 허용된 경직만 막는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 결과 타입·Stamina·Stagger·Super Armor 기반을 유지하고 실제 방패 접촉과 행동 전환을 검증한다.
6. **작은 단위의 점진적 전환 순서:** 회피 무적 → 방향 가드 → Stamina → Guard Break → 패리 → 강인도·슈퍼아머.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 결과별 체력·자원·상태 전환이 Player와 적에서 동일하고 PlayMode와 Profiler 기록이 있다.

### 마일스톤 8. 점프·낙하·착지와 점프 공격

1. **목표 동작 정의:** 지상 이탈부터 착지까지 예측 가능하며 점프 공격이 공중 상태와 충돌 규칙을 우회하지 않는다.
2. **입력 → 처리 → 출력:** 점프·공격 요청과 지면 상태 → 상승·낙하·착지·점프 공격 전환 → 모터 이동과 Animator 출력.
3. **책임 경계와 데이터 소유자:** 모터는 수직 충돌, 공중 상태는 전환, 전투는 점프 공격의 판정 구간을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 공중 재점프는 금지하고 낮은 천장 충돌은 상승을 끝내며 착지 강도에 따라 회복 시간을 결정한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 중력·접지 계산을 출발점으로 사용하되 명시적 점프·낙하·착지 상태를 추가한다.
6. **작은 단위의 점진적 전환 순서:** 점프 → 천장 → 낙하 → 착지 → 단차 → 점프 공격.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 프레임별 높이·거리 허용 오차, 천장·경사 착지와 점프 공격 1회 판정을 확인한다.

### 마일스톤 9. 일반 인간형 적 1대1 결투

1. **목표 동작 정의:** 적이 거리와 각도를 만들고 준비·타격·회복 책임을 지며 읽을 수 있는 결투를 제공한다.
2. **입력 → 처리 → 출력:** 플레이어 위치·이전 행동·쿨다운 → 이동·공격·대기 선택 → 공통 모터와 타격 결과.
3. **책임 경계와 데이터 소유자:** AI는 의도 선택, 공통 행동·모터·타격 계층은 실행과 결과를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 공격 가능 위치를 만들지 못하면 재배치하고 벽에서는 공격을 강행하거나 무제한 회전하지 않는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 Zombie와 인간형 적 상태를 참고하되 새 계약을 통과한 한 종류만 먼저 완성한다.
6. **작은 단위의 점진적 전환 순서:** 접근·이탈 → 단일 공격 → 두 공격 선택 → 피격·방어 → 우발적 다수 조우 안전 규칙.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 다양한 거리·벽·기둥 배치에서 무한 추적·겹침 없이 1대1 전투를 반복 재현한다.

### 마일스톤 10. 경량·중량 무기 확장성 검증

1. **목표 동작 정의:** 빠른 경량 무기와 느린 중량 무기가 같은 계약을 사용하면서 거리·회복·강인도 차이를 보인다.
2. **입력 → 처리 → 출력:** 무기별 행동 설정 → 공통 구간·모터·궤적·결과 처리 → 서로 다른 감각과 동일한 규칙.
3. **책임 경계와 데이터 소유자:** 무기 데이터는 값과 형상만 바꾸며 상태 머신과 타격 계산을 복사하지 않는다.
4. **실패·중단·충돌·상태 전환 규칙:** 설정 누락은 명시적으로 실행을 거부하고 한손검 기본값을 묵시적으로 섞지 않는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 공격별 설정 배열과 공통 감지기를 활용하되 무기 계열별 예외 분기를 제한한다.
6. **작은 단위의 점진적 전환 순서:** 경량 단일 공격 → 경량 연계 → 중량 단일 공격 → 슈퍼아머 → 세 무기 회귀.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 새 무기 추가가 기존 상태 코드를 복사하지 않고 동일 자동·PlayMode·Profiler 기준을 통과한다.

### 마일스톤 11. NightShade 공격 패턴·페이즈·보스 카메라 통합

1. **목표 동작 정의:** 인간형 크기의 긴 창 보스가 실제 사거리, 제한 추적, 페이즈 변화와 읽을 수 있는 카메라를 제공한다.
2. **입력 → 처리 → 출력:** 거리·각도·이전 공격·쿨다운·체력 구간 → 공격·연계·이동 성향 선택 → 공통 전투 결과와 보스 카메라.
3. **책임 경계와 데이터 소유자:** NightShade AI는 선택과 페이즈만, 공통 계층은 이동·타격·방어 결과, 카메라는 구도를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 창이 벽에 닿으면 반동하고, 연계는 지정된 분기 시점에만 판단하며 무제한 목표 추적을 금지한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 13개 패턴과 거리·각도·가중치·쿨다운·페이즈·연계를 유지하고 창 구간·벽·공통 결과를 연결한다.
6. **작은 단위의 점진적 전환 순서:** 실제 사거리 → 최소 거리 → 벽 → 연계 분기 → 페이즈 → 강인도 → 카메라.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 창 끝·중간·손잡이, 좁은 공간, 페이즈 전환과 락온 해제를 자동 테스트와 PlayMode로 확인한다.

### 마일스톤 12. Hit Stop·VFX·Audio·카메라 반응과 절차적 자세 보정

1. **목표 동작 정의:** 결과 강도가 화면·소리·자세에 일치하되 판정과 조작을 왜곡하지 않는다.
2. **입력 → 처리 → 출력:** 확정된 접촉·결과·강도 → 제한된 반응 조합 → 국소 Hit Stop, 효과, 카메라와 IK.
3. **책임 경계와 데이터 소유자:** 전투는 의미 데이터, 표현 계층은 자산 선택과 재생, 카메라는 흔들림·FOV 상한을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** Disable·사망·중복 결과에서 재생 속도와 IK 가중치를 복구하고 반응 합산 상한을 넘지 않는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 접촉점·강도·Hit Stop 입력을 활용하며 표현 자산 참조를 핵심 계산에서 분리한다.
6. **작은 단위의 점진적 전환 순서:** 국소 정지 → 접촉 VFX → Audio → 흔들림 → FOV → Foot/Look/Hand IK.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 다중 타격에도 상한이 지켜지고 Hit Stop 중 카메라 입력·충돌 복구가 계속되며 GC 목표를 충족한다.

### 마일스톤 13. 성능·프레임별 판정·좁은 공간 회귀

1. **목표 동작 정의:** 30·60·120 FPS와 복잡한 지형에서 이동·판정·카메라 결과가 일관된다.
2. **입력 → 처리 → 출력:** 고정 재현 입력과 지형 배치 → 프레임·Profiler·결과 비교 → 회귀 보고서와 허용 오차.
3. **책임 경계와 데이터 소유자:** 자동 테스트는 수치, PlayMode는 조작·가독성, Profiler는 비용 증거를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 허용 오차를 벗어난 항목은 완료를 취소하고 원인 영역 단계로 되돌린다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 NonAlloc·캐시·Sweep 기반을 유지하며 전체 프레임과 좁은 공간 증거를 추가한다.
6. **작은 단위의 점진적 전환 순서:** 이동 → 회피 → 공격 → 방어 → 카메라 → NightShade → 복합 장면.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 거리·타격 횟수·해제 규칙이 일관되고 반복 검색 구간의 관리 힙 `GC Alloc 0 B` 목표를 기록한다.

### 마일스톤 14. 초거대 보스와 게임패드 후속 확장

1. **목표 동작 정의:** 검증된 인간형 계약 위에 다중 락온 지점, 특수 구도와 게임패드 입력을 추가한다.
2. **입력 → 처리 → 출력:** 새 입력 장치·대형 보스 표적 정보 → 기존 요청·후보·카메라 문맥 확장 → 장치와 크기에 맞는 출력.
3. **책임 경계와 데이터 소유자:** 장치 어댑터와 대형 보스 카메라만 확장하고 핵심 행동·타격 의미는 유지한다.
4. **실패·중단·충돌·상태 전환 규칙:** 락온 지점 상실 시 다른 지점 또는 자유 시점으로 예측 가능하게 전환한다.
5. **현재 구현에서 보존할 점과 부족한 점:** Input Actions와 후보 서비스 확장성을 사용하며 인간형 전용 가정을 목록화한다.
6. **작은 단위의 점진적 전환 순서:** 게임패드 매핑 → 장치 전환 → 다중 표적 → 대형 보스 피벗 → 특수 거리·가림.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 기존 키보드·마우스와 인간형 전투 회귀를 깨지 않고 별도 자동·PlayMode·Profiler 기준을 통과한다.

## 8. 통합 완료 조건

다음 시나리오를 하나의 테스트 빌드에서 연속 수행해야 통합 로드맵의 인간형 범위를 완료한다.

1. 자유 시점으로 경사·계단·문·기둥을 통과한다.
2. 소프트 보정으로 일반 인간형 적에게 한손검 공격을 시도한다.
3. 수동 락온으로 스트레이프하며 회피·가드·패리와 Guard Break를 확인한다.
4. 벽 가까이에서 공격하여 이동 정지와 벽 반동을 확인한다.
5. 점프·낙하·착지와 점프 공격을 수행한다.
6. 경량·중량 무기로 같은 계약이 유지되는지 비교한다.
7. NightShade의 최소 거리, 창 사거리, 제한 연계, 페이즈와 보스 카메라를 확인한다.
8. Hit Stop 중 카메라를 움직이고 장애물 충돌 복구가 계속되는지 확인한다.
9. 같은 시나리오를 30·60·120 FPS에서 실행해 이동 거리와 타격 횟수를 비교한다.
10. Profiler에서 정상 이동·카메라·타격 반복 구간의 관리 힙 `GC Alloc 0 B` 목표와 물리 질의 수를 기록한다.

초거대 보스와 게임패드는 이 완료 조건에 포함하지 않는다. 인간형 기준이 완료된 뒤 마일스톤 14의 별도 완료 기록으로 관리한다.
