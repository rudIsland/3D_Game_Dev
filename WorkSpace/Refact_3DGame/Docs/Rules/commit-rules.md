# 커밋 규칙

이 문서는 Refact_3DGame의 공통 커밋 기준이다. Project_P의 로컬 전용 커밋 규칙 원문은 확보하지 못했으므로 아래 형식은 이 프로젝트용으로 정했다.

## 범위와 시점

1. 사용자가 요청하거나 이미 허용한 범위에서 커밋한다. 파일 작성·수정 요청을 자동 커밋이나 원격 푸시 요청으로 간주하지 않는다.
2. 한 커밋에는 하나의 변경 목적을 담는다. 기능 수정과 그 설명 문서·필수 에셋 변경은 함께 묶을 수 있다.
3. 폴더 이동과 기능 변경은 검토하기 쉽게 구분한다. 같은 작업이 여러 커밋으로 나뉘더라도 각 커밋의 필요한 참조·설정을 빠뜨리지 않는다.
4. 동시 작업이 있는 저장소에서는 이번 작업의 파일이나 변경 구간만 스테이징한다. 전체 변경을 한꺼번에 추가하지 않는다.
5. 관계없는 변경, 기존 스테이징, 다른 작업자의 커밋을 임의로 되돌리거나 수정하지 않는다.

## 메시지 형식

```text
종류(대상): 변경 내용

필요할 때 변경 이유와 확인 결과를 덧붙인다.
```

| 종류 | 용도 |
| --- | --- |
| feat | 기능 추가 |
| fix | 오류 수정 |
| refactor | 구조·책임 정리 |
| perf | 근거가 있는 성능 개선 |
| docs | 문서·규칙 수정 |
| style | 동작 변경 없는 서식 정리 |
| chore | 도구·설정·의존성·빌드 작업 |

대상은 map, player, rules처럼 변경 위치가 드러나게 적고, 내용은 한국어로 작성한다. 작은 변경은 제목만으로 충분하다.

예: docs(rules): 공통 규칙과 세션 기록 위치 정리
예: refactor(map): 씬 캐시와 참조 횟수 관리로 단순화

## 포함할 파일

1. Unity 에셋·스크립트를 추가·이동·삭제하면 대응하는 .meta도 함께 확인한다. 이동 시 기존 GUID를 유지한다.
2. 변경에 필요한 씬·프리팹·설정·asmdef·asmref와 관련 문서를 빠뜨리지 않는다.
3. Library, Temp, Logs, obj, IDE 자동 생성 파일과 빌드 결과는 커밋에 포함하지 않는다. 기존 .gitignore 적용 여부를 확인한다.
4. Docs/Rules는 공유할 규칙 원문이므로 저장소에 포함한다. 세션 기록을 포함할 때는 해당 작업에 필요한 내용만 남기고 토큰·계정 정보·개인 경로를 적지 않는다.

## 커밋 전후 확인

1. git status와 diff로 수정·신규·삭제 파일을 확인한다.
2. 스테이징한 diff를 읽고 다른 작업의 변경이 섞이지 않았는지 확인한다.
3. 변경 규모에 맞는 검증 결과를 남긴다. 새 테스트 파일·테스트 케이스는 만들지 않는다. 보류한 검증을 통과로 적지 않는다.
4. 커밋 후 대상 파일과 메시지를 확인하고 남아 있는 변경을 구분한다.
5. 커밋과 푸시는 구분한다. 원격 반영은 사용자가 요청하거나 허용한 범위에 한한다.
