# 속성 간소화 결과 (2026-09-25)

## 범위와 판단 기준

직접 작성한 `Assets/_Project` C# 220개 파일을 대상으로 속성 선언과 실제 참조를 분석했다. Unity의 어셈블리 참조·전처리 조건으로 컴파일러 심벌을 대조해 같은 이름의 다른 타입을 구분하고, 인터페이스 구현·상속 계약도 확인했다. 패키지·외부 에셋과 자동 생성 Input System 코드는 수정하지 않았다.

기존 흐름은 설정 입력 → 실행 설정 복사·판정 → 상태 변경·이벤트 → HUD·게임 흐름이다. 호출되지 않는 조회, 결과 계산에만 잠깐 필요한 복사값, 같은 값을 다시 노출하는 중간 속성을 줄였다. 직렬화 필드 이름·타입·에셋 값과 이벤트·상태 전환 순서는 유지했다.

### 처리 순서가 유지되는 부분

- ZombieSettings는 Inspector의 원래 거리·각도를 읽어 기존과 같은 거리 제곱·방향 내적 기준을 만든다. 계산 결과만 보관하며 프레임마다 다시 계산하지 않는다.
- PlayerCharacterConfig의 Inspector 설정은 유지한다. 최대 체력은 이미 보관하던 `Life.MaxHealth`에서 읽는다. 방어 각도는 기존 `MinimumGuardDot` 계산에 그대로 들어간다.
- NightShade 경직 피해는 기존의 `피해 × 1`에서 동일한 피해 값 직접 전달로 줄였다. 경직 누적·반응 선택·이벤트 순서는 같다.
- PlayerHitRequest의 HitSurface는 저장만 하고 읽지 않았다. 해당 값과 전달 인자를 제거했으며, 좀비·NightShade의 방패/몸통 접촉 후보 우선순위와 실제 방어 판정·결과별 효과는 유지했다.
- 로딩 현황은 화면에서 읽는 주소·종류·요청 횟수·핸들 유효 여부만 복사한다. 로드·반환·핸들 보관은 바꾸지 않았다.

## 유지한 속성과 이유

- **Inspector 설정의 읽기 전용 접근:** 직렬화 필드를 외부에서 임의 수정하지 못하게 한다. 조절 가능한 값을 const로 바꾸지 않는다.
- **실행 설정 복사본:** 설정 원본과 실행 중 값을 구분하고 곡선을 복사하는 기존 정책을 유지한다. 이름이 같다는 이유만으로 합치지 않는다.
- **HUD·상호작용 인터페이스:** 엔티티 구현을 모르는 호출자가 사용하는 계약이다. 고정 문자열·bool을 반환하더라도 계약 구현이면 유지한다.
- **계산된 상태·생명주기·풀 소유 상태:** 현재 상태나 불변 조건을 보호하며 실제 호출자가 사용한다.
- **NightShade 진단 기록:** 읽는 게임 코드가 없어도 행동 선택의 점수 내역·후보·전환·중단 이유를 디버거로 관찰하는 역할이 있다. CombatDebug 경로와 점수 구성 요소는 유지했다. 런타임 필드를 모두 전역으로 옮기지 않는다.

## 확인과 남은 작업

- 컴파일러 기반 전체 참조 분석에서 오류 0. 제거 후 사용처가 끊긴 속성도 다시 확인했다.
