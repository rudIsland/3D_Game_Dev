# 소울류 전투 로드맵

## 1. 목적과 책임 범위

이 문서는 플레이어와 인간형 적이 같은 행동·타격 의미를 사용하여 무게 있는 근접 결투를 만드는 순서를 정의한다. 첫 완성 무기는 한손검과 방패이며, 이후 빠른 경량 무기와 느린 중량 무기로 같은 계약의 확장성을 검증한다.

이 문서가 소유하는 범위는 다음과 같다.

- 행동 요청, 요청 버퍼, 행동 우선순위와 취소 표
- 준비·실제 작동·회복 구간과 구간별 회전·이동 제한
- 한손검 공격, 회피, 가드, 패리, Stamina, Guard Break
- 접촉 표면, 타격 Queue 수명, 순수 결과 계산과 Unit 일괄 반영
- 무기 궤적, 벽 반동, 경직, 강인도와 슈퍼아머
- 일반 인간형 적의 결투 행동과 우발적인 다수 조우 안전 규칙
- NightShade의 창 사거리, 공격 선택, 연계 분기, 페이즈와 공통 결과 연결
- 타격 결과를 입력으로 받는 Hit Stop·VFX·Audio·카메라 반응의 전투 측 계약

다음 책임은 다른 문서가 소유한다.

- 지면·경사·계단·벽을 적용한 최종 이동: [SoulslikeCharacterMovementRoadmap.md](SoulslikeCharacterMovementRoadmap.md)
- 자유 시점·소프트 보정·락온 후보와 보스 구도: [SoulslikeCameraRoadmap.md](SoulslikeCameraRoadmap.md)
- 전체 마일스톤과 통합 완료 조건: [SoulslikeGameplayRoadmap.md](SoulslikeGameplayRoadmap.md)

무기 대 무기의 임의 충돌과 튕김은 이번 인간형 범위에서 제외한다. 무기 충돌처럼 보이는 결과는 활성 방패 표면의 가드 또는 명시적인 패리 창에서만 만든다.

## 2. 목표 전투 경험

### 2.1 거리와 방향

- 공격은 실제 무기 길이와 궤적 안에서만 맞는다.
- 자유 시점 공격은 카메라와 이동 의도 안의 후보를 제한 각도만큼만 보정한다.
- 수동 락온 공격은 대상 중심 방향을 사용하지만 준비 구간의 허용 회전 각도를 넘지 않는다.
- 실제 타격 구간에 들어가면 플레이어와 적 모두 무제한 추적을 멈춘다.
- 긴 무기는 최소 공격 거리를 가질 수 있다. 너무 가까운 대상은 창 끝이 아니라 손잡이·몸통 접촉 규칙 또는 재배치 행동으로 처리한다.

### 2.2 시간과 책임

- 준비 구간은 읽고 대응할 시간이며 제한적인 방향 보정만 허용한다.
- 실제 작동 구간은 공격 판정·회피 무적·패리 판정이 발생하고 일반 취소를 막는다.
- 회복 구간은 실패한 공격의 책임이며 초반 이동·회전을 고정한다.
- 회복 후반의 명시된 창에서만 다음 공격·회피·가드 요청을 실행한다.
- 성공 여부와 관계없이 행동이 소비한 Stamina와 위치 위험은 사라지지 않는다. 예외는 별도 설계된 환급 규칙만 허용한다.

### 2.3 공통 결과 의미

Player, 일반 적과 NightShade는 같은 결과 이름을 같은 의미로 사용한다. 이 문서의 타격 판정 상세 계약이 접촉 선택, 계산 순서, 수치 반영과 상태 전환의 단일 기준이다.

| 결과 | 체력·자원 | 행동 전환 의미 |
| --- | --- | --- |
| `Ignored` | 변경 없음 | 현재 행동 유지 |
| `Dodged` | 피해 없음 | 공격자는 공격을 계속하고 피해자는 회피 유지 |
| `Parried` | 피해자 피해 없음 | 공격자를 Parried 상태로 강제 전환 |
| `Guarded` | 방어자 Stamina 감소 | 방어자는 가드 반응, 공격자는 설정된 반동만 적용 |
| `GuardBroken` | 방어자 Stamina 소진 | 방어자를 Guard Break로 강제 전환 |
| `Damaged` | 체력·경직 수치 반영 | 슈퍼아머 등으로 현재 행동을 유지할 수 있음 |
| `Staggered` | 체력·경직 수치 반영 | 현재 공격을 중단하고 강한 피격 전환 |
| `KnockedDown` | 체력·경직 수치 반영 | 넘어짐과 회복 전환 |
| `Killed` | 사망 처리 | 모든 공격·방어 창과 요청 정리 |

## 3. 행동 계약

### 3.1 행동 요청

입력 콜백은 상태를 직접 바꾸지 않고 장치와 무관한 요청을 만든다. 구현 시 이름은 역할이 드러나도록 `AttackRequest`, `DodgeRequest`, `GuardRequest`, `JumpRequest`처럼 대상 또는 의도와 행동을 함께 표현한다.

요청이 최소한 가져야 할 정보는 다음과 같다.

- 요청 종류
- 눌림·유지·해제 중 필요한 입력 단계
- 입력이 발생한 시각 또는 요청 나이
- 이동 또는 조준 방향의 입력 스냅샷
- 이미 소비되었는지 구분할 수 있는 실행 번호

버퍼는 작은 고정 크기 또는 행동 종류별 한 칸을 우선한다. 같은 입력이 여러 프레임 유지되어도 한 번만 실행하며, 새 요청이 기존 요청을 덮는 규칙을 종류별로 명시한다. 매 프레임 컬렉션·열거자·클로저를 만들지 않는다.

### 3.2 행동 구간과 허용 표

각 행동 설정은 애니메이션 측정 결과를 바탕으로 다음 값을 가진다.

- 준비·실제 작동·회복 경계
- 준비 중 최대 방향 보정 각도와 초당 회전 속도
- 코드 이동 또는 Root Motion 사용 여부와 이동 배율
- 공격 판정, 무적, 가드와 패리 활성 창
- 다음 행동별 버퍼 소비 시작 시점
- 결과 종류별 중단 가능 여부
- Stamina 비용, 강인도와 슈퍼아머 창
- 벽 접촉 시 반동 종류와 공격 종료 규칙

공통 기본 허용은 다음과 같다. 최종 수치는 클립 측정과 PlayMode로 확정한다.

| 현재 구간 | 사망·강제 결과 | 방향 보정 | 공격 요청 | 회피 요청 | 가드 요청 | 점프 요청 |
| --- | --- | --- | --- | --- | --- | --- |
| 준비 | 즉시 중단 | 제한 허용 | 연계용 저장 | 설정된 취소만 | 설정된 취소만 | 일반적으로 저장 또는 거부 |
| 실제 작동 | 즉시 중단 | 강하게 고정 | 저장만 | 저장만 | 저장만 | 저장 또는 만료 |
| 회복 초반 | 즉시 중단 | 고정 | 저장 | 저장 | 저장 | 저장 |
| 회복 후반 | 즉시 중단 | 다음 행동이 허용한 보정 | 허용 첫 프레임 실행 | 허용 첫 프레임 실행 | 허용 첫 프레임 실행 | 허용 첫 프레임 실행 |

`공격 → 회피`가 항상 가능하거나 항상 불가능한 전역 규칙은 두지 않는다. 각 공격의 취소 창을 명시하고, 실제 타격 이전·중·이후를 혼동하지 않는다.

### 3.3 우선순위와 한 번만 실행

```text
사망
→ Knockdown·Guard Break·Parried
→ 강한 피격·Staggered
→ 공격·회피·가드·점프 요청
→ 일반 이동
```

한 프레임에 결과가 여러 개면 공통 타격 Queue가 결과 순서를 확정한 뒤 상태 머신이 가장 높은 강제 전환을 한 번 적용한다. 행동 요청은 강제 결과가 끝난 뒤에도 유효하고 해당 상태가 버퍼 소비를 허용할 때만 실행한다. 실행한 요청은 즉시 제거하여 Animator 이벤트와 Update 양쪽에서 중복 실행되지 않게 한다.

### 3.4 행동 실패와 정리

- Stamina 부족, 공중 제한, 무기 설정 누락, 대상 상실은 행동 시작 전 실패다.
- 시작 전 실패한 요청은 정책에 따라 짧게 유지하거나 즉시 만료하되 무한 재시도하지 않는다.
- 행동 중단 시 공격 판정, 무적, 패리, 가드 표면, 슈퍼아머, Root Motion 제출과 연계 분기 상태를 정리한다.
- Animation Event가 누락되어도 상태 종료 또는 Disable 경계에서 활성 판정을 닫는 안전 경로를 둔다.
- 이벤트가 두 번 호출되어도 종료·해제는 멱등적으로 동작해야 한다.

## 4. 목표 입력 → 처리 → 출력 흐름

### 4.1 플레이어 공격

```text
마우스 공격 입력
→ AttackRequest 기록
→ 현재 구간·우선순위·Stamina·지면 조건 검사
→ 자유 시점 소프트 후보 또는 락온 대상에서 제한 회전 목표 계산
→ 준비 구간 시작과 Root Motion 제출
→ 이전·현재 무기 형상 사이 궤적 및 환경 검사
→ 벽이면 공격·이동 종료와 반동 / Unit이면 타격 Queue 등록
→ 공통 결과 계산과 Unit 반영
→ 확정 결과에 맞는 Animator·VFX·Audio·카메라 반응
→ 회복 후반에 유효한 다음 요청 한 번 소비
```

### 4.2 방어와 패리

```text
가드 유지 또는 패리 입력
→ GuardRequest 또는 ParryRequest
→ 진입 가능 상태와 Stamina 검사
→ 방패 표면·패리 창 활성
→ 공격 궤적과 실제 표면 접촉 기록
→ 접촉 당시 방향·창·공격 설정으로 결과 계산
→ Guarded / GuardBroken / Parried / Damaged 중 하나 확정
→ 자원·상태·반동과 표현 적용
```

가드 방향은 캐릭터 정면만 보지 않고 실제 활성 방패 표면 접촉과 접촉 당시 방패 정면을 사용한다. 패리는 별도 활성 창과 패리 가능한 공격 설정이 모두 맞아야 한다.

### 4.3 적 공격 선택

```text
플레이어 거리·각도·가시성·현재 행동
+ 적의 이전 공격·쿨다운·페이즈·벽 여유
→ 사용할 수 없는 패턴 제외
→ 반복 억제와 가중치로 의도 선택
→ 공격 시작 위치와 준비 방향 확정
→ 공통 행동 구간·모터·무기 궤적 실행
→ 공통 타격 결과와 다음 의사결정
```

AI는 공격을 선택할 뿐 타격 성공이나 이동 충돌을 직접 확정하지 않는다.

## 5. 책임 경계와 데이터 소유자

| 데이터·행동 | 소유자 | 변경 시 함께 확인할 경계 |
| --- | --- | --- |
| 입력 눌림·유지·해제 | 입력 경계 | 재바인딩과 Disable 초기화 |
| 요청 나이와 소비 상태 | 행동 요청 버퍼 | 상태 전환과 Hit Stop 시간 정책 |
| 현재 행동과 구간 | 행동 상태 머신 | Animator 이벤트와 안전 종료 |
| 공격별 거리·각도·창·비용 | 공격 설정 | 클립 측정표와 무기 형상 |
| 최종 캐릭터 이동 | 캐릭터 모터 | Root Motion·벽·지면 결과 |
| 무기 이전·현재 형상 | 무기 감지기 | 활성 시작 프레임 초기화 |
| 접촉과 타격 Queue | 전투 감지·Resolver | 실행 번호와 대상별 중복 제거 |
| 체력·Stamina·Stagger·방어 상태 | Unit | Enable·Disable·사망 초기화 |
| 결과 계산 순서 | 공통 계산기 | Player·적·보스 공통 테스트 |
| 적 패턴 선택 | 적 공격 선택기 | 결정 가능한 분기 시점 |
| 애니메이션·효과 | 표현 경계 | 결과를 재판정하지 않음 |

외부 유료 서비스나 LLM은 전투 런타임의 필수 의존성이 아니다. 향후 원격 밸런스 분석이나 텔레메트리를 사용하더라도 측정 데이터 내보내기 경계 뒤에 두고, 오프라인에서도 동일한 행동·타격 결과가 나오게 한다.

## 6. 현재 구현에서 보존할 점과 부족한 점

### 6.1 현재 입력 → 처리 → 출력

현재 플레이어는 `PlayerInputReader`가 이동·공격·구르기·가드·락온 입력을 읽고, `PlayerStateMachine`과 하위 행동 상태가 이동·방어·구르기·공격을 전환한다. `PlayerAttackState`는 1~5단 공격과 달리기 공격을 재생하고 공격 입력 하나를 시간 버퍼에 보관한다. 공격 방향은 카메라 수평 전방을 사용하며 첫 공격은 즉시 회전하고, 후속 공격은 타격 종료 이벤트 뒤 열린 창에서만 회전한다.

공격 판정은 `MeleeHitDetector`가 활성 형상을 Overlap하고 이전 위치와 현재 위치 사이를 Sweep한다. 같은 공격 실행에서 같은 Unit을 한 번만 Queue에 넣고, 공통 전투 계산이 회피·패리·가드·피해·경직 결과를 만든다. `UnitStamina`, `UnitStagger`, `UnitDefenseStatus`와 Super Armor 기반도 존재한다.

NightShade는 거리·각도·페이즈·쿨다운·가중치·최근 공격과 연계를 사용해 13개 공격 중 하나를 선택한다. 공격 설정은 준비 중 회전, 활성 구간, 회복과 접근·이탈 그룹을 가진다.

### 6.2 보존할 기반

- 입력, 상태, 이동, Animator와 타격 계산을 나눈 현재 책임 경계
- 공격별 설정과 실행 번호
- 이동한 무기 형상을 검사하는 Sweep과 대상별 중복 제거
- 공통 Hit 입력·결과·Unit 자원과 방어 상태
- FreeLook/TargetLook 이동 모드와 카메라 기준 공격 방향
- NightShade의 데이터 기반 공격 후보 필터와 최근 공격 억제
- 반복 검색에서 재사용하는 배열·컬렉션과 NonAlloc 방향

### 6.3 부족한 점

- 공격 외 회피·가드·점프를 포함한 공통 요청 버퍼와 취소 표가 없다.
- 현재 공격 중 구르기는 명시된 구간보다 상태 분기에서 즉시 취소될 수 있다.
- `AttackPhaseTracker`는 Zombie 공격에 연결되어 있지만 Player와 NightShade가 같은 구간 계약을 공유하지 않는다.
- Player의 구간은 Animator normalized time과 이벤트, NightShade의 구간은 패턴 시간으로 나뉘어 공통 의미 검증이 어렵다.
- 무기 궤적이 Unit은 찾지만 환경 벽 접촉 뒤 이동·타격 중단과 전용 반동 계약이 없다.
- 현재 가드·패리·Stamina 데이터가 실제 방패 표면, 행동 전환, 모든 Unit의 PlayMode 결과까지 완료되었다고 볼 증거가 부족하다.
- 점프·낙하·착지 상태와 점프 공격이 없다.
- NightShade 창의 끝·중간·손잡이 접촉 의미, 최소 거리와 벽 여유가 공격 선택·결과에 완전히 연결되지 않았다.

현재 구현 비교는 목표를 줄이는 근거로 사용하지 않는다. 각 단계에서는 보존할 작은 책임을 재사용하고 부족한 계약만 좁게 추가한다.

## 7. 타격 판정·Unit 생명주기 상세 계약

이 절은 접촉이 발생한 뒤 결과가 확정되고 표현 계층에 전달될 때까지의 단일 기준이다. 행동 상태는 공격 창을 열고 닫지만 피해를 직접 계산하지 않으며, Animator·VFX·Audio·카메라는 확정된 결과를 바꾸지 않는다.

### 7.1 전체 입력 → 처리 → 출력

```text
공격 요청 또는 Enemy AI 판단
→ 행동 상태가 준비 구간 시작
→ Animation Event 또는 측정된 구간이 무기 판정 활성화
→ 이전·현재 무기 형상 사이 Unit·방어 표면·환경 Sweep
→ 대상별 가장 이른 접촉과 가장 이른 환경 접촉 비교
→ 벽이 먼저면 공격 이동·판정 종료와 벽 반동
→ Unit이 먼저면 공격 실행 번호 + 대상 기준으로 Queue에 한 번 보관
→ Queue 추가 시 대상 활성 상태와 ActivationSequence 기록
→ 같은 프레임 후보 수집 종료
→ 적용 직전 대상 활성 상태·ActivationSequence·공격 실행 번호 재확인
→ Unit.ReceiveAttackHit
→ AttackHitResultCalculator가 부작용 없이 결과 계산
→ Unit이 Health·Stamina·Stagger를 한 번에 반영
→ 파생 Unit이 결과 종류에 맞는 상태 전환만 선택
→ 공격자에게 확정 결과 이벤트 전달
→ 피격 이동·Animator·VFX·Audio·카메라가 결과 표현
```

Unit 접촉이 벽보다 먼저 발생했다면 그 접촉은 현재 공격 실행의 결과 후보로 유지하고 이후 판정을 닫는다. 벽이 먼저 발생했다면 벽 너머 Unit 접촉은 Queue에 넣지 않는다. 물리 API의 반환 순서가 아니라 Sweep 진행률로 순서를 결정한다.

### 7.2 반드시 지킬 불변 규칙

1. 결과 계산이 끝나기 전에는 Health, Stamina, Stagger와 상태 머신을 변경하지 않는다.
2. 계산기는 대상 현재값을 읽고 `AttackHitResult`만 반환한다.
3. 확정 수치는 Unit의 한 적용 메서드에서 각 자원에 한 번만 반영한다.
4. 파생 Player·Enemy·Boss Unit은 공통 판정을 복사하지 않고 상태 전환만 선택한다.
5. `Killed`는 `Staggered`와 `KnockedDown`보다 항상 우선한다.
6. `Dodged`, `Parried`, `Ignored`는 피해자의 Health·Stamina·Stagger를 변경하지 않는다.
7. `Guarded`는 Health·Stagger를 변경하지 않고 방어자 Stamina만 한 번 감소시킨다.
8. `GuardBroken`은 첫 구현에서 체력 피해를 함께 주지 않고 남은 Stamina를 0으로 만든다.
9. 슈퍼아머는 체력·경직 수치 반영을 막지 않고 행동 중단 결과만 조정한다.
10. 같은 공격 실행은 한 Unit에 한 번만 적용되고 다음 공격 실행에서는 다시 맞을 수 있다.
11. Disable된 Unit과 이전 풀 활성 주기의 Unit은 Queue에 남은 타격도 받지 않는다.
12. 같은 프레임에 이미 Queue에 들어간 양쪽 공격은 한쪽의 피격으로 Detector가 닫혀도 함께 적용될 수 있어야 한다.
13. 물리 검색 반환 순서와 Collider 등록 순서는 접촉 표면 우선순위를 바꾸지 않는다.
14. 연출 실패는 결과 종류와 자원 값을 되돌리거나 변경하지 않는다.
15. Update·LateUpdate·타격 검색에는 LINQ, 클로저, 반복 문자열·배열 생성과 반복 `GetComponent`를 추가하지 않는다.
16. Disable·Dead·Guard Break·상태 Exit에서는 공격 판정과 모든 방어 창을 멱등적으로 닫는다.

### 7.3 무기·방패·신체·환경 접촉 선택

무기 감지기는 Collider를 찾는 즉시 결과를 확정하지 않는다. 한 물리 갱신에서 발견한 후보를 Receiver별로 모은 뒤 다음 순서로 하나를 선택한다.

1. 이전 형상과 현재 형상 사이 Sweep 및 현재 형상 Overlap 결과를 수집한다.
2. Collider에서 공격 가능 Receiver, 신체 부위와 `HurtBox`/`GuardSurface` 종류를 찾는다.
3. 동일 Receiver의 접촉 진행률과 현재 Overlap 거리를 비교한다.
4. 진행률이 더 낮은, 즉 무기 궤적에서 먼저 닿은 표면을 선택한다.
5. 진행률 차이가 작은 허용 오차 안일 때만 `GuardSurface`를 우선한다.
6. 모든 물리 검색이 끝난 뒤 Receiver마다 한 후보만 Queue에 추가한다.
7. 같은 진행률 기준으로 가장 이른 환경 접촉도 비교해 벽 뒤 후보를 제거한다.

가드 성공에는 가드 중 활성화된 방패 Trigger인 `UnitGuardHitBox`와 실제 접촉이 필요하다. 비가드 상태의 방패와 등에 멘 방패는 공격 후보에 참여하지 않는다.

접촉 스냅샷은 최소한 다음 값을 가진다.

- 접촉 표면 종류
- 접촉점과 Normal
- 공격 진행 방향과 무기 Sweep 진행률
- 신체 부위
- 접촉 당시 방패 정면

`GuardSurface`가 먼저 닿아도 공격이 방어 불가이거나 접촉 당시 방패 정면 범위를 벗어나면 체력 피해 판정으로 진행한다. Queue 적용 시점의 현재 `IsGuarding`이나 현재 방패 Transform으로 이미 성립한 접촉을 다시 판단하지 않는다. 같은 프레임에 가드 입력이 해제되어도 접촉 당시 활성 표면은 해당 접촉까지 유효하다.

검색 배열이 가득 차거나 공격 시작 형상이 대상 내부에 있으면 Development 환경에서 공격 실행당 한 번만 고정 문자열 경고를 남긴다. 정상 타격 프레임에는 로그와 문자열을 만들지 않는다.

### 7.4 Queue·공격 실행·풀 활성 주기

Queue 항목은 다음 수명을 식별할 값을 보관한다.

- 공격을 시작한 Detector와 공격 실행 번호
- 대상 Receiver
- Queue 추가 당시 대상 `ActivationSequence`
- 확정 전 접촉을 포함한 `AttackHitInput`

Queue 추가 시점과 적용 시점 모두 `CanTakeHit`을 검사한다. 적용 시점에는 대상 `ActivationSequence`와 Detector 공격 실행 번호도 다시 확인한다.

공격 실행 번호 규칙은 다음과 같다.

- `StartHit`은 새 실행 번호를 만든다.
- 새 공격이 시작되면 이전 공격의 대기 타격은 실행 번호 불일치로 폐기한다.
- 일반 `EndHit`은 이미 같은 프레임 Queue에 들어간 동시 타격을 보존하기 위해 번호를 바꾸지 않는다.
- Detector `OnDisable`은 실행 번호를 무효화하여 풀 재사용 뒤 옛 타격을 폐기한다.
- 실행 번호가 최대값에 도달하면 0을 유효값으로 사용하지 않고 안전한 첫 값으로 순환한다.

Unit의 `ActivationSequence`는 Enable될 때만 증가한다. 일시적인 공격 종료나 Hit 상태 전환은 이 값을 바꾸지 않는다. Player Disable/Enable은 기존 체력을 유지하고, 풀 Enemy Enable은 해당 정책에 따라 체력과 Stamina를 초기화하되 이전 Queue 항목은 새 활성 주기에 적용되지 않아야 한다.

### 7.5 순수 결과 계산 순서

결과 계산기는 다음 순서를 사용한다.

```text
비활성·사망·아군·잘못된 공격
→ Ignored

회피 무적
→ Dodged

패리 창 + 패리 가능 공격
→ Parried

GuardSurface + 방어 가능 공격 + 접촉 당시 정면 각도
→ Stamina 충분: Guarded
→ Stamina 부족: GuardBroken

방어 불가 GuardSurface 또는 정면 범위 밖
→ 체력 피해 판정으로 관통

치명 피해
→ Killed

Knockdown 공격 + 허용된 중단
→ KnockedDown

경직 한계 도달 + 슈퍼아머 없음
→ Staggered

그 외 유효 피해
→ Damaged
```

가드 각도는 접촉 당시 방패 정면과 공격이 날아온 수평 방향의 내적으로 계산한다. 두 방향 중 하나가 0에 가까우면 정면 가드로 인정하지 않는다. `CanBeBlocked`와 `CanBeParried`는 공격 설정이며 이름을 `Guarded` 결과와 혼동하지 않는다.

같은 입력과 같은 대상 스냅샷은 같은 결과를 내야 한다. 계산 중에는 대상 값이 바뀌지 않으며, 치명 피해는 경직·Knockdown보다 먼저 `Killed`를 반환한다.

### 7.6 Unit 자원·상태 생명주기

공통 Unit은 Health, Stamina, Stagger와 DefenseStatus를 소유하고 다음 순서를 한곳에서 보장한다.

```text
Create
→ 자원·계산기 생성
→ 파생 Unit 연결

Enable
→ ActivationSequence 증가
→ 방어 창과 경직 초기화
→ Player/Enemy별 자원 Reset 정책 적용
→ 파생 상태 머신 Enable

Tick
→ 경직 회복
→ Stamina 회복
→ 파생 입력 또는 AI 갱신

Disable
→ 무적·가드·패리·슈퍼아머와 공격 판정 종료
→ 파생 상태 머신 Disable

Dispose
→ 이벤트 구독 해제
→ 중복 호출 안전 보장
```

타격 수신은 다음 한 경로를 사용한다.

```text
ReceiveAttackHit
→ CalculateResult
→ ApplyAttackHitResult
→ HandleAttackHitResult
→ AttackHitResult 반환
```

`ApplyAttackHitResult`는 결과에 들어 있는 HealthDamage, StaminaDamage와 StaggerDamage만 적용한다. `HandleAttackHitResult`는 파생 Unit의 상태 머신 경계이며 수치를 다시 계산하지 않는다.

| 결과 | 자원 반영 | 방어자 행동 | 공격자 행동 |
| --- | --- | --- | --- |
| `Ignored` | 없음 | 유지 | 유지 |
| `Dodged` | 없음 | 회피 유지 | 공격 유지 |
| `Parried` | 피해자 변화 없음 | 패리 유지 | 공격 판정 종료와 Parried 전환 |
| `Guarded` | Stamina만 감소 | 가드 유지와 충격 표현 | 설정된 반동 또는 공격 유지 |
| `GuardBroken` | Stamina 0 | Guard Break 전환 | 공격 판정 종료 정책 적용 |
| `Damaged` | Health·Stagger 반영 | 기본적으로 현재 행동 유지 | 공격 유지 |
| `Staggered` | Health·Stagger 반영 | 공격 종료와 Hit 전환 | 공격 유지 |
| `KnockedDown` | Health·Stagger 반영 | 공격 종료와 Knockdown 전환 | 공격 유지 |
| `Killed` | Health 0 | 모든 행동 종료와 Dead 전환 | 공격 결과 표현 |

전용 Knockdown 상태와 클립이 없는 Unit은 Knockdown 데이터를 일반 Hit 애니메이션으로 임시 소비하지 않고 `allowsKnockdown = false`로 시작한다. Boss 차이는 `if (IsBoss)` 판정 복사보다 StaggerLimit, Knockdown 허용과 슈퍼아머 구간 설정으로 표현한다.

### 7.7 방어 창과 GuardHitBox 생명주기

- Roll 무적은 Roll 상태 전체가 아니라 클립에서 측정한 실제 Animation Event 구간에만 연다.
- 패리 창과 슈퍼아머도 측정된 시작·종료 이벤트 또는 같은 의미의 명시적 구간으로 연다.
- Guard 진입은 DefenseStatus와 GuardHitBox 활성 순서를 한 Controller 경계에서 보장한다.
- Guard Exit는 GuardHitBox와 DefenseStatus를 같은 생명주기에서 닫는다.
- `GuardBroken`은 GuardHitBox를 먼저 닫고 공격 판정을 종료한 뒤 전용 상태로 전환한다.
- 상태 Exit, Disable과 Dead는 이벤트 누락과 중복 호출에 관계없이 모든 창을 닫는다.
- 방어 불가 공격은 패리·가드 창에 들어와도 다음 유효 결과 계산으로 내려간다.
- 가드 충격 애니메이션은 `Guarded` 결과를 소비하지만 결과를 다시 계산하지 않는다.

Inspector와 Scene에서는 GuardHitBox Trigger, 시작 비활성 상태, HurtBox/GuardSurface Layer, 공격 검색 LayerMask, Physics Collision Matrix, 방패 정면 Transform과 공격별 `CanBeBlocked`·GuardStaminaDamage를 함께 확인한다.

### 7.8 확정 결과 이벤트와 연출 입력

표현 계층에 전달할 입력은 다음으로 제한한다.

- `AttackHitResult.Type`
- 실제 반영된 Health·Stamina·Stagger 수치
- 반응 강도와 방향
- 접촉점과 Normal
- 신체·방어 표면 종류
- Hit Stop 시간

`Guarded`는 방패 접촉점의 불꽃·금속음·약한 카메라 반응, `Parried`는 공격자 경직·강한 금속음·짧은 Hit Stop, `Damaged` 이상은 접촉 부위와 강도에 맞는 반응을 사용한다. `Dodged`와 `Ignored`는 체력 피격 VFX를 만들지 않는다.

결과 이벤트는 Controller 생성 경계에서 메서드 그룹으로 한 번 구독하고 Destroy/Dispose에서 해제한다. 여러 공격 설정이 같은 Detector를 참조해도 중복 구독하지 않으며 공격마다 람다를 만들지 않는다. 효과 재생 실패와 풀 고갈은 판정 결과를 바꾸지 않는다.

Hit Stop은 전역 `Time.timeScale`을 사용하지 않고 공격자·피해자의 Animator와 행동 갱신만 제한한다. Disable·Dead·씬 종료에서는 재생 속도와 정지 상태를 반드시 복구한다. 카메라 입력과 충돌 복구는 [SoulslikeCameraRoadmap.md](SoulslikeCameraRoadmap.md)의 비정지 시간 정책을 따른다.

### 7.9 상세 구현 순서

상위 전투 마일스톤 안에서 타격 하위 계약은 다음 순서로만 확장한다.

1. 현재 Player ↔ 일반 인간형 적의 피해·경직·동시 타격·Profiler 기준선을 기록한다.
2. Unit 자원과 Enable/Tick/Disable/Dispose 순서를 공통 생명주기로 모은다.
3. 결과 계산과 자원·상태 반영을 분리한다.
4. 공격 실행 번호, ActivationSequence와 동시 타격을 Queue 수명에 연결한다.
5. HurtBox와 활성 GuardSurface 후보를 물리 반환 순서와 무관하게 선택한다.
6. 회피·방향 가드·패리·Guard Break·강인도·슈퍼아머를 결과 표에 연결한다.
7. 벽에 막힌 피격 이동과 확정 결과 연출을 판정에서 분리한다.
8. 같은 계약을 NightShade와 다른 Unit에 적용한다.

각 하위 단계는 자동 테스트, Unity PlayMode와 Profiler 조건을 모두 기록한 뒤 다음 단계로 이동한다. NightShade의 공통 결과 연결은 보스 패턴 전체 완성보다 먼저 수행할 수 있지만 전용 결과 의미를 추가하지 않는다.

### 7.10 상세 자동·PlayMode·Profiler 완료 조건

자동 테스트는 최소한 다음 사례를 포함한다.

- 결과 계산이 대상 값을 변경하지 않음
- 같은 입력과 스냅샷이 같은 결과를 반환
- 잘못된 공격·아군·사망 대상은 `Ignored`
- 치명 피해가 `Staggered`·`KnockedDown`보다 `Killed` 우선
- 무적 대상은 `Dodged`, 유효 패리는 `Parried`
- 정면 GuardSurface와 충분한 Stamina는 `Guarded`
- 측면·후면·방어 불가 GuardSurface는 체력 피해
- Stamina 부족은 `GuardBroken`
- 가드 접촉 뒤 같은 프레임 Exit가 스냅샷을 무효화하지 않음
- `Guarded`가 Health·Stagger를 바꾸지 않고 Stamina를 한 번만 변경
- Disable 또는 새 ActivationSequence 대상의 대기 타격 폐기
- 새 공격 시작 전 이전 실행의 대기 타격 폐기
- 일반 EndHit 전 이미 Queue에 들어간 동시 타격 유지
- Detector Disable이 이전 Queue 항목 무효화
- 같은 공격의 다수 HitBox가 Unit에 한 번만 적용되고 다음 공격은 다시 적용
- 최소 전투 간격이 접근만 막고 측면·후퇴·수직 이동 유지
- 효과 실패가 결과·피해를 바꾸지 않고 Disable이 정지 Animator를 복구

Unity PlayMode에서는 Player 방패와 일반 인간형 적 공격으로 정면 `Guarded`, 측면 관통, 몸이 방패보다 먼저 닿는 경우, Guard Break, Roll 무적 경계, 패리 가능·불가 공격, 동시 타격, 풀 재활성화와 벽 피격 이동을 확인한다. Animator 상태·파라미터와 GuardHitBox 활성 여부도 함께 기록한다.

Profiler에서는 타격 활성 구간 관리 힙 `GC Alloc 0 B`, 반복 `GetComponent`·Scene 검색 없음, 검색 버퍼 사용량, 물리 질의 수, 이벤트 중복 구독 없음과 VFX·Audio 반복 Instantiate/Destroy 없음을 확인한다. 완료 프레임 기준은 30·60·120 FPS이며 15 FPS는 누락 원인을 찾는 선택적 스트레스 진단으로만 사용한다.

## 8. 단계별 구현 로드맵

### 전투 0단계. 행동·클립·무기 기준선 측정

1. **목표 동작 정의:** 한손검·방패의 준비·실제 작동·회복, 거리, 회전, Root Motion과 방어 창을 측정 가능한 기준으로 만든다.
2. **입력 → 처리 → 출력:** 고정 공격·회피·가드 입력 → 클립 프레임·무기 위치·Root Motion 기록 → 행동별 측정표.
3. **책임 경계와 데이터 소유자:** 측정 도구는 관찰만 하고 행동 설정의 최종값은 전투 데이터가 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 이벤트와 실제 접촉 프레임이 다르면 임의로 맞추지 않고 둘 다 기록해 원인을 분리한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 공격 번호·이동 스케일·타격 설정을 기준선으로 보존하지만 완료값으로 간주하지 않는다.
6. **작은 단위의 점진적 전환 순서:** 공격 1 → 나머지 콤보 → 달리기 공격 → 구르기 → 가드·패리 순서로 측정한다.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 측정 재현 테스트, Animator·무기 Gizmo PlayMode 확인, 활성 구간 물리 검색과 GC 기준선을 기록한다.

### 전투 1단계. 공통 행동 요청·우선순위·취소 계약

1. **목표 동작 정의:** 공격·회피·가드·점프 요청을 즉시 수집하고 허용 첫 프레임에 한 번만 실행한다.
2. **입력 → 처리 → 출력:** 입력 단계와 방향 스냅샷 → 고정 요청 버퍼·우선순위·취소 표 → 하나의 행동 전환.
3. **책임 경계와 데이터 소유자:** 입력은 요청 생성, 버퍼는 유효성, 상태 머신은 실행 허용, 행동 설정은 구간별 취소를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 만료·자원 부족·강제 결과 시 요청 유지 또는 제거 규칙을 종류별로 고정한다.
5. **현재 구현에서 보존할 점과 부족한 점:** `PlayerAttackState`의 한 번 소비와 만료 개념을 보존하되 공격 상태 내부 전용 버퍼에서 공통 경계로 옮긴다.
6. **작은 단위의 점진적 전환 순서:** 공격 요청 → 회피 요청 → 가드 눌림·해제 → 점프 자리만 마련 → 강제 결과 우선순위.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 경계 프레임, 동시 입력, 만료, 중복 이벤트, Disable 정리를 테스트하고 반복 입력 `GC Alloc 0 B`를 목표로 한다.

### 전투 2단계. 한손검·방패 공격 구간과 Root Motion

1. **목표 동작 정의:** 단일 공격과 콤보가 측정된 구간, 제한 회전과 충돌된 전진 거리를 사용한다.
2. **입력 → 처리 → 출력:** 유효 AttackRequest → 공격 설정·소프트/락온 방향 → 구간 전환·Root Motion 제출·Animator 재생.
3. **책임 경계와 데이터 소유자:** 공격 상태는 구간과 연계, 이동 문서는 최종 충돌, Animator는 표현과 측정 이벤트를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 실제 작동 중 일반 취소 금지, 회복 후반만 다음 요청 소비, 강제 결과는 즉시 공격 창을 닫는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 5단 콤보·달리기 공격·카메라 방향·후속 회전 창을 보존하고 공통 구간 의미에 연결한다.
6. **작은 단위의 점진적 전환 순서:** 공격 1 구간 → 공격 1 이동 충돌 → 2단 연계 → 5단 → 달리기 공격.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 큰 목표 각도, 타격 순간 방향 고정, 회복 입력, 벽 앞 전진 거리와 30·60·120 FPS 일관성을 확인한다.

### 전투 3단계. 무기 연속 궤적과 벽 반동

1. **목표 동작 정의:** 검이 한 프레임 사이를 빠르게 지나도 대상을 놓치지 않고 벽 접촉은 공격 실패로 읽힌다.
2. **입력 → 처리 → 출력:** 이전·현재 무기 형상과 환경/Unit 레이어 → Sweep·접촉 우선순위·중복 제거 → Unit 타격 또는 벽 반동.
3. **책임 경계와 데이터 소유자:** 감지기는 접촉 후보, 환경 판정은 벽 결과, Resolver는 Unit Queue, 행동 상태는 공격 종료를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 활성 시작 시 이전 형상을 초기화하고 벽 접촉 뒤 같은 실행 번호의 Unit 타격과 이동을 닫는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 현재 Overlap·Sphere/Box Cast·실행 번호·대상 중복 제거를 보존하고 환경 결과를 추가한다.
6. **작은 단위의 점진적 전환 순서:** 검 한 형상 → 빠른 횡베기 → 찌르기 → 벽 레이어 → 반동 상태 → 좁은 통로.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 30·60·120 FPS 타격 횟수, 얇은 벽·기둥·문틀 반동, 활성 검색 `GC Alloc 0 B`를 확인한다.

### 전투 4단계. 회피 무적과 구간별 취소

1. **목표 동작 정의:** 방향 회피가 실제 무적 구간과 Root Motion 거리를 가지며 공격 취소는 설정된 창에서만 발생한다.
2. **입력 → 처리 → 출력:** DodgeRequest와 방향 스냅샷 → 지면·Stamina·취소 창 검사 → 8방향 회피, 무적과 회복.
3. **책임 경계와 데이터 소유자:** 행동 상태는 회피 구간, Unit 방어 상태는 무적, 모터는 충돌된 거리, Animator는 방향 표현을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 공중·Stamina 부족은 시작 거부, 벽은 거리를 줄이고 남은 이동을 폐기, 사망·강제 결과는 무적을 정리한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 8방향 입력과 Root Motion 회피를 보존하고 즉시 공격 취소를 행동별 창으로 제한한다.
6. **작은 단위의 점진적 전환 순서:** 이동 중 회피 → 제자리 후방 회피 → 공격 취소 → 벽·경사 → 연속 입력.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 무적 경계 전후 피격, 한 번만 소비, 벽 관통 없음과 프레임별 회피 거리 허용 오차를 확인한다.

### 전투 5단계. 방향 가드·패리·Stamina·경직·강인도

1. **목표 동작 정의:** 방패가 실제 접촉한 정면 공격만 막고, 짧은 패리와 자원·강인도 결과가 명확하다.
2. **입력 → 처리 → 출력:** 가드·패리 요청과 공격 접촉 → 방패 표면·각도·창·Stamina·공격 설정 계산 → Guarded·GuardBroken·Parried·피해 결과.
3. **책임 경계와 데이터 소유자:** Guard/Parry 상태는 활성 창, Unit은 자원, 계산기는 결과, 공격 상태는 반동과 Parried 중단을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 뒤·옆 공격과 방패를 빗나간 공격은 피해로 진행하고, Stamina 0은 Guard Break, 패리 불가 공격은 가드 또는 피해로 진행한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 공통 Stamina·Stagger·Super Armor·결과 타입을 보존하고 실제 표면 접촉과 공통 전환 표를 완성한다.
6. **작은 단위의 점진적 전환 순서:** 가드 표면 → 방향 → Stamina → Guard Break → 패리 → 강인도 → 공격 슈퍼아머.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 접촉 당시 가드 해제 경계, 뒤 공격, 동시 접촉, Player·적 동일 결과와 반복 가드 GC를 확인한다.

### 전투 6단계. 점프 공격

1. **목표 동작 정의:** 지상·공중 전환을 존중하며 착지 위치와 무기 궤적이 일치하는 점프 공격을 제공한다.
2. **입력 → 처리 → 출력:** 공중 AttackRequest와 수직 상태 → 점프 공격 허용·구간·낙하 보정 → 모터 이동, 1회 판정과 착지 회복.
3. **책임 경계와 데이터 소유자:** 공중 상태는 높이와 착지, 전투는 공격 창, 모터는 충돌, Animator는 자세를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 낮은 천장·벽·단차에서 이동을 강행하지 않고 착지 전 판정 종료와 사망 정리를 보장한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 공격 감지와 공통 결과를 재사용하며 별도 점프 전용 타격 계산을 만들지 않는다.
6. **작은 단위의 점진적 전환 순서:** 공중 요청 → 공격 자세 → 무기 창 → 착지 → 경사·벽 → 락온 방향 제한.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 한 점프 한 타격, 천장·벽·경사 착지, 프레임별 낙하와 접촉 일관성을 확인한다.

### 전투 7단계. 일반 인간형 적 1대1과 다수 조우 안전 규칙

1. **목표 동작 정의:** 한 적은 거리를 만들고 읽을 수 있는 공격을 하며, 우발적 다수 조우도 불공정한 동시 압박을 제한한다.
2. **입력 → 처리 → 출력:** 거리·각도·가시성·공격권·쿨다운 → 접근·대기·공격·이탈 선택 → 공통 행동과 타격 결과.
3. **책임 경계와 데이터 소유자:** 개별 AI는 후보 행동, 조우 조정은 최소 공격권, 공통 계층은 실행과 결과를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 벽·다른 Unit 때문에 공격 위치를 못 만들면 재배치하고 화면 밖 연속 공격과 같은 프레임 다중 강공을 제한한다.
5. **현재 구현에서 보존할 점과 부족한 점:** Zombie/NightShade의 거리·각도 선택과 공통 Unit 결과를 참고하되 첫 인간형 적 하나로 계약을 검증한다.
6. **작은 단위의 점진적 전환 순서:** 1대1 접근 → 두 공격 → 회복 → 피격 → 가드 가능 공격 → 우발적 2대1 공격권.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 평지·벽·기둥에서 무한 회전·겹침 없이 결투하고, 2대1에서 최소 안전 규칙과 AI GC를 확인한다.

최소 안전 규칙은 대규모 군중 전투 시스템이 아니다. 동시에 실제 공격 구간에 들어갈 수 있는 적 수 제한, 화면 밖 강공 경고, 공격권을 얻지 못한 적의 거리 유지 정도만 두고 레벨 배치상 1대1을 우선한다.

### 전투 8단계. 경량·중량 무기 확장

1. **목표 동작 정의:** 경량은 짧은 준비·낮은 경직, 중량은 긴 준비·큰 회복·강인도로 차별화되지만 같은 규칙을 사용한다.
2. **입력 → 처리 → 출력:** 무기별 설정·형상 → 공통 요청·구간·모터·궤적·결과 → 무기별 거리와 전달감.
3. **책임 경계와 데이터 소유자:** 무기 설정은 값·형상·Animator 키만 소유하고 상태 머신·Resolver·Unit 결과를 복사하지 않는다.
4. **실패·중단·충돌·상태 전환 규칙:** 필수 형상·구간·클립이 없으면 실행을 거부하고 묵시적 기본 공격으로 대체하지 않는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 공격 번호별 `AttackHitSettings` 방향을 유지하며 무기 계열 데이터와 검증 도구를 보완한다.
6. **작은 단위의 점진적 전환 순서:** 경량 단타 → 경량 연계 → 중량 단타 → 중량 슈퍼아머 → 방어 상호작용 → 세 무기 회귀.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 새 무기 추가에 전용 결과 분기가 없고 거리·타격 횟수·GC·Animator 연결이 기준을 통과한다.

### 전투 9단계. NightShade 창·연계·페이즈

1. **목표 동작 정의:** 현재 인간형 크기 또는 약간 큰 NightShade가 긴 창의 실제 장단점과 체력 구간별 전투 성향을 보인다.
2. **입력 → 처리 → 출력:** 거리·각도·가시성·이전 공격·쿨다운·체력 구간·벽 여유 → 공격·연계·재배치 선택 → 공통 이동·타격·보스 반응.
3. **책임 경계와 데이터 소유자:** 패턴은 선택 조건과 분기 시점, AI는 의도, 창 감지기는 접촉, 공통 Unit은 결과 의미를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 최소 거리 안에서는 부적합한 찌르기를 제외하고, 창 벽 접촉은 반동하며, 연계는 지정된 분기 시점에서만 한 번 결정한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 13개 ID, 그룹·페이즈 마스크·가중치·쿨다운·최근 공격·연계를 보존하고 창 구간과 제한 분기를 추가한다.
6. **작은 단위의 점진적 전환 순서:** 창 끝 사거리 → 중간·손잡이 → 최소 거리 → 벽 → 분기 시점 → 체력 페이즈 → 이동 성향·강인도.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 끝·중간·손잡이 접촉, 반복 억제, 분기 후 추적 고정, 페이즈, 공통 결과와 보스전 GC를 확인한다.

NightShade도 별도 `BossDamage`나 전용 피격 예외를 만들지 않는다. 페이즈 갱신은 공통 결과가 체력에 반영된 뒤 실행하고, `Damaged`, `Staggered`, `KnockedDown`, `Killed`의 전환 의미는 Player와 일반 적의 표와 같다.

### 전투 10단계. 결과 연출과 전체 회귀

1. **목표 동작 정의:** 공격 강도와 결과가 Hit Stop·VFX·Audio·카메라에 일치하고 프레임·좁은 공간에서도 규칙이 유지된다.
2. **입력 → 처리 → 출력:** 확정 접촉·결과·강도 → 표현 프로필과 중첩 상한 → 국소 정지, 효과, 카메라 반응과 회귀 기록.
3. **책임 경계와 데이터 소유자:** 전투는 결과 데이터만 제공하고 각 표현 계층은 자산과 재생 수명을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 효과 누락은 전투 결과를 되돌리지 않으며 Disable·사망에서 재생 속도·풀·반응을 정리한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 접촉 위치·강도·Hit Stop 입력을 활용하고 실제 자산 연결과 중첩 상한을 완성한다.
6. **작은 단위의 점진적 전환 순서:** Hit Stop → VFX → Audio → 카메라 → 다중 결과 상한 → 30·60·120 FPS·좁은 공간 회귀.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 결과별 연출, Hit Stop 중 카메라 지속, 거리·타격 횟수 일관성과 반복 구간 `GC Alloc 0 B` 목표를 기록한다.

## 9. NightShade 세부 완료 기준

### 9.1 크기와 무기

- 현재 인간형 크기를 기본으로 사용하고 가독성을 위해 필요할 때만 약간 확대한다.
- 확대 전후 `CharacterController`, 피격 HitBox, 발 위치, 창 형상과 카메라 피벗을 함께 재측정한다.
- 창은 최소한 끝, 중간, 손잡이 구간을 구분할 수 있어야 한다.
- 각 공격은 실제로 사용하는 구간과 피해·경직 의미를 설정한다. 단순히 창 Collider 전체에 같은 피해를 주지 않는다.
- 찌르기, 횡베기, 내려찍기의 이전·현재 형상 Sweep을 30·60·120 FPS에서 비교한다.

### 9.2 공격 선택과 연계

- 후보 필터: 페이즈, 최소·최대 거리, 허용 각도, 가시성, 벽 여유, 쿨다운.
- 점수: 이전 공격, 최근 반복, 공격 그룹, 현재 이동 성향과 페이즈 가중치.
- 연계 판단은 준비 중 또는 첫 타격 뒤처럼 패턴에 기록된 분기 시점에서 한 번만 한다.
- 분기 뒤에는 새 목표 위치를 매 프레임 다시 계산하지 않는다. 허용된 제한 회전만 적용한다.
- 대상이 분기 유효 범위를 벗어나면 억지 추적 대신 연계 중단, 짧은 회복 또는 재배치를 선택한다.

### 9.3 페이즈

체력 경계값은 임의로 고정하지 않고 패턴 수와 실제 전투 길이를 측정해 확정한다. 페이즈 변화는 다음 묶음을 바꿀 수 있다.

- 사용할 수 있는 공격 조합
- 접근·유지·이탈 거리 성향
- 연계 확률과 재사용 시간
- 공격별 준비·회복 속도 범위
- 강인도와 슈퍼아머 창
- 보스 카메라의 제한된 거리·FOV 프로필

페이즈 전환 자체가 플레이어 위치로 순간 이동하거나 무제한 회전하는 근거가 되어서는 안 된다.
