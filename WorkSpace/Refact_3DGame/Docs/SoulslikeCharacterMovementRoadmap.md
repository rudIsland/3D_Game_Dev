# 소울류 캐릭터 이동 로드맵

## 1. 목적과 책임 범위

이 문서는 플레이어와 인간형 적의 실제 위치를 하나의 운동학적 충돌 규칙으로 확정하는 순서를 정의한다. 목표는 애니메이션을 그대로 재생하는 것이 아니라, 발 디딤·Root Motion·벽·지면·피격 이동이 하나의 결과를 가리키게 만드는 것이다.

이 문서가 소유하는 범위는 다음과 같다.

- 지상 이동, 회전, 접지, 중력, 경사, 계단, 벽과 단차
- 자유 이동과 락온 스트레이프가 공유하는 캐릭터 모터
- 일반 코드 이동, 공격·회피 Root Motion과 피격 결과 이동의 조합
- 점프, 상승, 낙하, 착지와 점프 공격을 위한 이동 경계
- Foot IK, 시선과 제한적인 손·무기 접촉 보정의 적용 순서
- 사망 애니메이션과 선택적인 래그돌 전환의 이동 측 계약

행동 요청·공격 구간·타격 결과 의미는 [SoulslikeCombatRoadmap.md](SoulslikeCombatRoadmap.md), 카메라 구도와 충돌은 [SoulslikeCameraRoadmap.md](SoulslikeCameraRoadmap.md), 전체 순서는 [SoulslikeGameplayRoadmap.md](SoulslikeGameplayRoadmap.md)가 소유한다.

## 2. 목표 이동 계약

### 2.1 하나의 충돌 몸체

- 살아 있는 일반 행동에서는 하나의 운동학적 충돌 몸체를 유지한다.
- 이동·공격·회피마다 `Rigidbody`와 운동학적 몸체를 전환하지 않는다.
- 최종 위치는 캐릭터 모터 경계를 통해서만 변경한다.
- `transform.position` 직접 변경과 `Rigidbody.AddForce`를 일반 이동·공격·피격에 섞지 않는다.
- 사망 래그돌은 필요한 적만 애니메이션 안정화 뒤 명시적으로 한 번 전환한다.

현재 프로젝트의 `CharacterController`는 이 계약을 점진적으로 구현할 수 있는 출발점이다. 이번 로드맵은 새 물리 패키지나 Rigidbody 기반으로 즉시 교체하는 계획이 아니다.

### 2.2 이동 소스

행동은 위치를 직접 바꾸지 않고 이번 갱신에 사용할 이동량을 제출한다.

| 이동 소스 | 예 | 소유 데이터 | 기본 우선순위 |
| --- | --- | --- | --- |
| 일반 이동 | 걷기·달리기·락온 스트레이프 | 입력 방향과 목표 속도 | 일반 |
| 행동 Root Motion | 공격·회피·가드 이동 | Animator delta와 행동 배율 | 일반 이동 대체 |
| 결과 이동 | 피격 밀림·Guard Break·Knockdown | 확정된 방향·거리·시간 | 행동 설정에 따른 강제 이동 |
| 수직 이동 | 중력·점프·낙하·착지 | 수직 속도와 접지 결과 | 다른 수평 소스와 합성 |

동일 프레임에 여러 수평 소스를 단순 합산하지 않는다. 현재 행동과 타격 결과 우선순위가 하나의 주 수평 소스를 선택하고, 수직 이동을 합성한 뒤 모터가 충돌을 적용한다.

### 2.3 입력 → 처리 → 출력

```text
행동 상태의 이동 의도
+ Animator에서 읽은 Root Motion
+ 확정된 피격 이동
+ 수직 속도
→ 현재 행동 우선순위에 따라 한 프레임 이동 요청 구성
→ 지면·경사·계단·벽·천장·단차 검사
→ 허용 변위와 충돌 결과 확정
→ 운동학적 몸체에 한 번 적용
→ 실제 속도·접지·벽 접촉·남은 이동 0으로 갱신
→ Animator 파라미터와 IK가 확정 결과를 표현
```

`Animator.deltaPosition`과 `deltaRotation`은 입력 데이터다. Animator가 충돌을 우회해 Transform을 직접 움직이지 않는다. 벽 때문에 적용되지 않은 Root Motion은 소비된 것으로 처리하며 다음 프레임에 더하지 않는다.

### 2.4 이동 모드

자유 이동과 락온 스트레이프는 방향 계산만 다르다.

| 모드 | 입력 방향 해석 | 회전 | 공유하는 것 |
| --- | --- | --- | --- |
| 자유 이동 | 카메라 수평 전방·오른쪽 기준 | 유효 이동 방향을 향해 회전 | 속도 제한, 가속·감속, 지면·경사·계단·벽·중력 |
| 락온 스트레이프 | 카메라 기준 전후좌우 | 대상 수평 방향을 향해 제한 회전 | 자유 이동과 같은 모터·충돌·접지 |

락온 상태가 바뀌어도 충돌 몸체, 접지 상태와 수직 속도를 초기화하지 않는다. 대상 상실 시 현재 실제 속도를 유지한 채 자유 모드로 전환하여 방향이 튀지 않게 한다.

## 3. 지면과 충돌 규칙

### 3.1 접지

- 접지는 `isGrounded` 한 값만 믿지 않고 실제 하향 이동 결과, 지면 법선과 허용 거리를 함께 기록하는 방향으로 개선한다.
- 지면에 서 있을 때 작은 하향 속도 또는 접지 보정을 사용하되 경사 아래로 과도하게 끌어당기지 않는다.
- 경사 경계와 계단에서 한 프레임 접지가 흔들려도 공격·회피가 잘못 공중 취급되지 않게 측정 기반의 짧은 안정 규칙을 검토한다.
- 공중 상태로 확정되면 접지 보정 대신 중력을 적용한다.

### 3.2 경사·계단·단차

- 오를 수 있는 경사와 계단은 설정된 최대 각도·높이 안에서 이동을 유지한다.
- 너무 가파른 경사는 위쪽 접근 성분을 제거하고 미끄러짐 정책을 명시한다.
- 작은 계단을 오를 때 실제 수평 속도가 불필요하게 0이 되지 않게 한다.
- 내려가는 계단과 경사에서 캡슐이 허공에 뜨거나 매 프레임 접지/공중을 반복하지 않게 한다.
- 허용되지 않은 단차는 벽처럼 막고, 낙하 가능한 가장자리는 명시적으로 공중 상태로 전환한다.

### 3.3 벽·문·기둥·천장

- 벽 접촉은 막힌 방향과 실제 적용 이동량을 결과로 남긴다.
- 기둥 가장자리에서는 허용된 접선 방향 이동을 유지하고 벽 쪽 성분만 줄인다.
- 좁은 문과 통로에서 캐릭터 몸체가 들어갈 수 없으면 Root Motion을 강행하지 않는다.
- 낮은 천장에 머리가 닿으면 점프 상승 속도를 끝내고 낙하로 전환한다.
- 공격 무기의 벽 접촉은 전투 감지기가 판단하지만, 몸체 Root Motion 정지는 모터가 판단한다. 두 결과는 같은 프레임 기록으로 비교한다.

### 3.4 다른 Unit과 최소 거리

Player, 일반 적과 NightShade의 이동은 같은 최소 전투 간격 제한을 사용한다. 상대에게 파고드는 수평 성분만 줄이고 측면 이동·후퇴·수직 이동은 유지한다. 이 제한은 일반 이동, Block Root Motion, 공격·회피 Root Motion, 추격과 피격 이동 중 정책상 허용된 모든 소스에 동일하게 적용한다.

최소 간격은 밀어내기 물리나 순간이동이 아니다. 두 Unit이 이미 겹친 상태에서는 서로 더 깊게 들어가는 성분을 먼저 막고, 안전하게 빠져나가는 방향을 허용한다.

`UnitMovementSeparation`은 이동을 직접 적용하지 않는 순수 제한 단계로 유지한다. 캐릭터 모터가 선택한 이번 프레임의 요청 변위를 전달하면, Unit 전용 LayerMask와 생성 시 캐시한 재사용 CapsuleCast 결과 배열로 가장 가까운 유효 Unit까지 허용되는 접근량만 계산한다. 물리 검색 반환 순서는 사용하지 않고 모든 후보 중 가장 제한적인 허용 거리를 선택한다.

```text
일반 이동 / Block Root Motion / 공격·회피 Root Motion / 피격 이동
+ Enemy 추격·공격 이동
→ CharacterMotor가 주 이동 소스와 수직 이동 선택
→ UnitMovementSeparation.LimitApproachMovement
→ 지면·경사·계단·벽·천장 충돌 해결
→ CharacterController.Move
→ 실제 변위와 접촉 결과 반환
```

행동이나 Enemy 종류가 별도 최소 간격 계산을 복사하지 않는다. 가드 여부와 관계없이 같은 기준을 사용하며, 최소 간격 때문에 줄어든 공격 Root Motion은 다음 프레임에 누적하지 않는다. 반복 경로에서는 LINQ, 클로저, 프레임별 배열과 반복 `GetComponent`를 사용하지 않는다.

최소 간격 자동 테스트는 접근 정지, 측면·후퇴·수직 보존, 여러 Unit 중 가장 가까운 허용 거리, 이미 겹친 상태의 이탈, 모든 이동 소스의 동일 제한 경로를 포함한다. Unity PlayMode에서는 일반 이동, Block·공격·회피 Root Motion, 피격 밀림과 Enemy 추격·공격이 서로의 몸체 안으로 들어가지 않는지 확인한다.

## 4. 행동별 이동 규칙

### 4.1 일반 이동

- 입력 벡터는 대각선 속도가 커지지 않게 크기 1로 제한한다.
- 카메라 수평 축을 사용하고 카메라가 수직을 볼 때는 마지막 유효 수평 방향 또는 캐릭터 전방으로 안전하게 대체한다.
- 걷기·달리기 속도 전환은 조작과 Animator 표현이 같은 실제 속도를 보게 한다.
- 가속·감속을 추가할 때 입력 반응을 해치지 않도록 먼저 현재 즉시 속도 기준선을 측정한다.

### 4.2 공격·회피 Root Motion

- 공격과 회피는 행동 설정이 선택한 Root Motion 배율을 적용한다.
- 준비·실제 작동·회복 구간이 방향 보정과 회전을 제한한다.
- 모터는 Root Motion의 충돌을 해결하지만 공격 취소 가능 여부를 결정하지 않는다.
- 벽 접촉으로 줄어든 변위는 버리고 공격 전용 벽 반동 여부를 전투 계층에 알린다.
- 시각 발 위치와 실제 캡슐 위치가 어긋나면 먼저 클립·Root Motion 배율·충돌 결과를 조정하고 IK로 판정을 숨기지 않는다.

### 4.3 피격 이동

- 타격 계산은 방향, 거리, 강도와 결과 종류를 제공한다.
- 이동 계층은 시간에 따른 수평 이동량을 만들고 모터 충돌을 거쳐 적용한다.
- 벽에 막힌 피격 이동은 남은 거리를 다음 프레임에 누적하지 않는다.
- 슈퍼아머로 공격을 유지하더라도 설정된 작은 피격 이동을 허용할지 공격별로 명시한다.
- Knockdown과 사망 이동은 일반 `Damaged` 밀림과 별도 프로필을 사용하지만 같은 모터 경계를 통과한다.

### 4.4 점프·낙하·착지

점프는 최소한 다음 상태를 가진다.

```text
지상
→ 점프 시작
→ 상승
→ 정점
→ 낙하
→ 착지
→ 지상 또는 착지 회복
```

- 점프 요청은 지상 또는 측정으로 확정한 짧은 접지 허용 범위에서만 실행한다.
- 이번 범위에서는 공중 재점프를 허용하지 않는다.
- 점프 높이는 초기 수직 속도와 중력으로 계산하고 프레임에 따라 달라지지 않게 한다.
- 낮은 천장 충돌은 상승을 종료한다.
- 착지 강도는 낙하 속도·높이 기준으로 나누고 큰 낙하는 회복 또는 피해 결과에 연결할 수 있게 한다.
- 점프 공격은 전투 행동이지만 수직 상태와 착지 결과를 우회하지 않는다.
- 코요테 타임과 지상 직전 점프 버퍼는 기준선 조작에서 필요성이 확인될 때 행동 요청 계약 안에서 작은 단계로 추가한다.

## 5. 판정 이후의 시각 보정

### 5.1 적용 순서

```text
행동 이동 요청
→ 캐릭터 모터와 충돌 결과 확정
→ Animator의 기본 자세 계산
→ Foot IK
→ 시선 보정
→ 제한적인 손·무기 접촉 보정
→ 최종 렌더 자세
```

IK는 HitBox, 무기 궤적, 접지 또는 실제 충돌 위치를 바꾸지 않는다. IK가 꺼져도 게임 규칙과 타격 결과가 같아야 한다.

### 5.2 Foot IK

- 각 발의 지면 높이와 법선을 재사용 가능한 Raycast/SphereCast 결과로 구한다.
- 발이 실제로 지면을 지지하는 클립 구간에만 가중치를 올린다.
- 골반 높이 보정은 두 발 차이를 제한 범위에서 흡수하고 캡슐 위치를 바꾸지 않는다.
- 계단 모서리와 급경사에서 발이 비정상적으로 꺾이면 가중치를 줄인다.
- 점프·낙하·회피 실제 작동 중에는 동작을 방해하지 않도록 끈다.

### 5.3 시선과 손·무기

- 시선은 락온 또는 전투 관심 대상을 향하되 목·상체 각도 상한과 감쇠를 사용한다.
- 대상이 뒤로 넘어가면 머리를 비틀지 않고 가중치를 낮춘다.
- 손·무기 접촉 보정은 양손 파지나 지정된 접촉 연출에만 사용한다.
- 무기 끝을 목표 HitBox로 끌어당겨 빗나간 판정을 맞은 것처럼 만들지 않는다.
- 벽에 막힌 공격은 IK로 무기를 벽 너머에 배치하지 않고 전투의 반동 결과를 표현한다.

## 6. 사망과 선택적 래그돌

- 기본 사망은 애니메이션을 우선한다.
- 사망 진입 시 행동 요청, 공격 판정, 방어 표면, 무적과 일반 이동을 정리한다.
- 사망 애니메이션 중에도 몸체가 벽·바닥을 관통하지 않도록 모터가 Root Motion을 제한한다.
- 필요한 적만 애니메이션이 안정된 시점에 선택적으로 래그돌로 전환한다.
- 래그돌 전환은 캐릭터 캡슐 Disable, 각 Rigidbody·Collider Enable과 초기 속도 전달을 한 책임에서 수행한다.
- 재사용 풀 대상은 래그돌을 원래 본·몸체 상태로 완전히 복구할 수 있어야 한다.
- Player와 모든 적에 래그돌을 강제하지 않는다. 성능·연출 이점이 있는 대상만 사용한다.

## 7. 현재 구현에서 보존할 점과 부족한 점

### 7.1 현재 입력 → 처리 → 출력

현재 `PlayerMovement`는 `PlayerInputReader.MoveValue`를 자유 이동 또는 타겟 이동 모드가 카메라 기준 방향으로 바꾸고 `CharacterController.Move`에 속도와 중력을 전달한다. 자유 이동은 이동 방향을 향해 회전하고, 타겟 이동은 선택한 대상 방향을 향한 스트레이프를 만든다.

공격·구르기·가드와 사망은 Animator Root Motion을 받아 수평 배율과 수직 속도를 합친 뒤 `CharacterController.Move`로 적용한다. 피격 밀림은 별도 시간 기반 이동량을 만들고 같은 CharacterController에 적용한다. 일반 이동, 피격과 Root Motion이 같은 몸체를 사용한다는 점은 목표와 맞지만, 각각의 메서드가 최종 `Move`를 직접 호출하여 한곳에서 이동 소스·충돌 결과를 비교하기 어렵다.

현재 수직 이동은 접지 시 작은 하향값, 공중에서 중력 누적으로 처리한다. 점프 요청·상승·낙하·착지 상태는 없다.

### 7.2 보존할 기반

- Rigidbody를 섞지 않는 `CharacterController` 기반
- 자유 이동과 락온 스트레이프의 방향 계산 분리
- 입력 대각선 제한과 카메라 수평 방향 계산
- 공격·구르기·가드 Root Motion과 공격별 이동 배율
- 피격 방향·거리의 시간 기반 이동
- 컴포넌트와 값을 생성 시 캐시하는 일반 C# `PlayerMovement`

### 7.3 부족한 점

- 일반·Root Motion·피격 이동이 하나의 요청과 최종 적용 결과로 모이지 않는다.
- 벽·경사 때문에 실제로 줄어든 이동량과 원인을 행동 계층에 일관되게 돌려주는 계약이 없다.
- 공격 Root Motion이 벽에 막혀도 전투의 벽 반동과 동기화된 결과를 만들지 않는다.
- 접지·경사·계단·단차를 프레임별로 비교한 자동·PlayMode 근거가 부족하다.
- 점프·낙하·착지·점프 공격이 없다.
- Foot IK, 시선, 손·무기 보정과 선택적 래그돌의 판정 이후 경계가 아직 없다.

## 8. 단계별 구현 로드맵

### 이동 0단계. 클립·몸체·지형 기준선

1. **목표 동작 정의:** 현재 캡슐, 속도, 중력, Root Motion과 테스트 지형 결과를 재현 가능한 수치로 만든다.
2. **입력 → 처리 → 출력:** 고정 WASD·공격·회피·피격 입력 → 실제 변위·접지·충돌 기록 → 프레임별 기준선 표.
3. **책임 경계와 데이터 소유자:** 측정 도구는 관찰, 테스트 Scene은 지형, 이동 설정은 최종값을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 캡슐·Scene·클립 참조가 다르면 측정을 섞지 않고 조합별로 구분한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 CharacterController 설정과 이동 배율을 시작값으로 보존하고 새 완료값으로 단정하지 않는다.
6. **작은 단위의 점진적 전환 순서:** 평지 → 경사 → 계단 → 벽·기둥 → 문·통로 → Root Motion → 피격.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 30·60·120 FPS 거리, 충돌 결과, Animator delta와 이동 구간 GC·호출 수 기준선을 기록한다.

### 이동 1단계. 하나의 캐릭터 모터와 최종 이동 경계

1. **목표 동작 정의:** 모든 살아 있는 행동이 하나의 운동학적 몸체와 한 최종 이동 경계를 사용한다.
2. **입력 → 처리 → 출력:** 일반·Root Motion·피격·수직 이동 요청 → 우선순위와 합성 → CharacterController 적용과 결과 반환.
3. **책임 경계와 데이터 소유자:** 행동은 이동 요청, 모터는 충돌·실제 변위·접지, Controller는 호출 순서를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 중복 제출은 우선순위로 하나를 선택하고 Disable·사망에서는 요청을 비우며 잔여 이동을 저장하지 않는다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 `PlayerMovement`와 CharacterController를 유지하고 직접 `Move` 호출을 제출·적용 경계로 순차 이동한다.
6. **작은 단위의 점진적 전환 순서:** 일반 이동 → 수직 → 피격 → Block Root Motion → 회피 → 공격 → 적 이동.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 각 소스 단독·동시 우선순위, 한 갱신 한 최종 적용, 기존 평지 감각과 GC 목표를 확인한다.

### 이동 2단계. 지면·경사·계단·벽·단차

1. **목표 동작 정의:** 평지와 복잡한 지형에서 접지가 안정되고 허용되지 않은 표면을 관통하지 않는다.
2. **입력 → 처리 → 출력:** 목표 변위와 몸체 설정 → 지면 법선·Step·Slope·벽·단차 해결 → 허용 변위와 접촉 결과.
3. **책임 경계와 데이터 소유자:** 모터가 지형 결과를 소유하고 행동은 결과를 읽되 자체 Raycast로 다른 접지 판정을 만들지 않는다.
4. **실패·중단·충돌·상태 전환 규칙:** 가파른 경사·높은 계단·좁은 문은 위쪽/안쪽 성분을 막고, 가장자리 이탈은 공중 상태로 전달한다.
5. **현재 구현에서 보존할 점과 부족한 점:** CharacterController의 기본 충돌을 활용하고 접지 흔들림·실제 변위 기록을 보완한다.
6. **작은 단위의 점진적 전환 순서:** 접지 → 오르막·내리막 → 낮은 계단 → 높은 계단 → 벽·기둥 → 문·단차.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 테스트 지형 전 구간에서 떨림·관통 없이 30·60·120 FPS 실제 속도와 물리 질의 비용을 기록한다.

### 이동 3단계. 자유 이동과 락온 스트레이프 공유

1. **목표 동작 정의:** 두 모드는 방향과 회전만 다르고 속도·지면·충돌 결과는 동일한 모터를 사용한다.
2. **입력 → 처리 → 출력:** WASD·카메라·선택 대상 → 모드별 목표 방향 → 공유 이동 요청과 실제 속도.
3. **책임 경계와 데이터 소유자:** 이동 모드는 방향, 모터는 이동, 카메라 문서는 대상과 구도를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 대상 상실·죽음·거리 초과 시 수직 속도와 실제 이동을 유지하고 자유 이동으로 전환한다.
5. **현재 구현에서 보존할 점과 부족한 점:** `PlayerFreeLookMovement`와 `PlayerTargetMovement` 분리를 유지하고 공통 모터 결과를 사용하게 한다.
6. **작은 단위의 점진적 전환 순서:** 자유 방향 → 자유 회전 → 락온 방향 → 대상 회전 → 전환 연속성 → 벽 스트레이프.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 같은 입력의 모드별 방향, 락온 해제 순간, 기둥 주변 이동과 반복 방향 계산 `GC Alloc 0 B`를 확인한다.

### 이동 4단계. 공격·회피 Root Motion과 피격 이동 충돌

1. **목표 동작 정의:** 행동 애니메이션의 무게를 유지하면서 벽·Unit을 관통하거나 막힌 이동을 누적하지 않는다.
2. **입력 → 처리 → 출력:** Animator delta 또는 피격 결과 → 행동 배율·우선순위·최소 간격·모터 충돌 → 실제 변위와 벽 결과.
3. **책임 경계와 데이터 소유자:** Animator는 delta, 행동은 배율, 모터는 적용, 전투는 벽 반동·중단을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 벽에 막힌 성분과 잔여량을 버리고 공격 중단·피격 종료·사망 전환에서 제출 상태를 정리한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 공격별 이동 배율과 HitPush를 유지하며 직접 이동 적용을 공통 모터에 연결한다.
6. **작은 단위의 점진적 전환 순서:** Block → 회피 → 공격 1 → 나머지 공격 → 피격 → 적 추격·공격 → Unit 최소 거리.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 벽·문·기둥·좁은 통로에서 관통·잔여 이동이 없고 프레임별 거리와 GC를 기록한다.

### 이동 5단계. 점프·낙하·착지

1. **목표 동작 정의:** 키보드 점프가 즉시 읽히고 상승·정점·낙하·착지가 지형과 프레임에 일관된다.
2. **입력 → 처리 → 출력:** JumpRequest·접지·수직 속도 → 점프 허용·중력·천장·낙하·착지 계산 → 모터 수직 이동과 상태·Animator.
3. **책임 경계와 데이터 소유자:** 요청 버퍼는 입력, 공중 상태는 전환, 모터는 충돌, 전투는 점프 공격을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 공중 재점프 금지, 천장 충돌 시 상승 종료, 사망·Knockdown 우선, 착지 시 수직 잔여량 제거.
5. **현재 구현에서 보존할 점과 부족한 점:** 현재 중력과 접지 하향값을 기준선으로 사용하고 명시적 공중 상태를 추가한다.
6. **작은 단위의 점진적 전환 순서:** 평지 점프 → 천장 → 낙하 → 경사·계단 착지 → 단차 → 착지 회복 → 점프 공격 연결.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 30·60·120 FPS 높이·체공 시간, 천장·단차·경사 착지와 수직 갱신 GC를 확인한다.

### 이동 6단계. Foot IK·시선·손·무기 보정

1. **목표 동작 정의:** 확정된 이동과 판정을 바꾸지 않으면서 발·시선·파지 자세가 지형과 대상에 자연스럽게 맞는다.
2. **입력 → 처리 → 출력:** 모터 지면 결과·Animator 자세·관심 대상 → 제한된 IK 목표와 가중치 → 최종 시각 자세.
3. **책임 경계와 데이터 소유자:** IK는 표현만 소유하고 모터 접지·HitBox·무기 판정을 변경하지 않는다.
4. **실패·중단·충돌·상태 전환 규칙:** 대상·지면 상실, 점프·회피·사망과 Disable에서 가중치를 안전하게 낮추고 캐시를 정리한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 기존 Animator와 본 구조를 유지하며 새 보정은 단계별 토글로 비교 가능하게 한다.
6. **작은 단위의 점진적 전환 순서:** 한 발 → 두 발·골반 → 계단 → 시선 → 양손 파지 → 지정 접촉 연출.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** IK On/Off 판정 동일, 급경사·계단·뒤 대상 한계, 반복 Raycast와 Animator IK GC를 확인한다.

### 이동 7단계. 사망 안정화와 선택적 래그돌

1. **목표 동작 정의:** 사망 애니메이션이 지형을 존중하고 필요한 적만 안정적으로 래그돌로 한 번 전환된다.
2. **입력 → 처리 → 출력:** Killed 결과·사망 클립·안정화 시점 → 모터 정리·애니메이션 이동·선택 전환 → 정지 시체 또는 래그돌.
3. **책임 경계와 데이터 소유자:** 사망 상태는 전환, 모터는 전환 전 충돌, 래그돌 어댑터는 Collider/Rigidbody 생명주기를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 중복 사망과 Disable에 멱등적이며 전환 실패 시 애니메이션 시체를 안전한 기본으로 유지한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 현재 사망 Root Motion 적용을 보존하고 모든 캐릭터에 래그돌을 강제하지 않는다.
6. **작은 단위의 점진적 전환 순서:** 애니메이션 사망 벽 충돌 → 정지 → 적 하나 래그돌 → 풀 복구 → NightShade 필요성 판단.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 벽·계단 사망, 중복 결과, Enable 재사용, Rigidbody 안정화와 다수 시체 성능을 기록한다.

### 이동 8단계. 프레임·좁은 공간·성능 회귀

1. **목표 동작 정의:** 모든 이동 소스와 시각 보정이 30·60·120 FPS 및 복잡한 지형에서 일관된다.
2. **입력 → 처리 → 출력:** 고정 입력 재생·지형 조합 → 실제 변위·접촉·상태·비용 비교 → 회귀 보고서.
3. **책임 경계와 데이터 소유자:** 자동 테스트는 수치, PlayMode는 조작·Animator, Profiler는 비용을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 허용 오차·관통·할당 기준을 벗어나면 관련 단계 완료를 취소하고 원인 단계로 돌아간다.
5. **현재 구현에서 보존할 점과 부족한 점:** 캐시와 단순 흐름을 유지하며 측정으로 필요한 최적화만 추가한다.
6. **작은 단위의 점진적 전환 순서:** 일반 이동 → 스트레이프 → Root Motion → 피격 → 점프 → IK → 사망 → 복합 전투.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 전용 공간 전체, 프레임별 허용 오차, 관리 힙 `GC Alloc 0 B` 목표와 물리 질의 상한을 기록한다.

- 점프 초기 속도, 중력, 천장과 착지 전환
- 30·60·120 FPS 적분 허용 오차
- Disable·사망·래그돌 중복 호출 안전성

### 9.2 Unity PlayMode와 Inspector

- 평지·오르막·내리막·경사 경계에서 접지와 Animator 값을 확인한다.
- 낮고 높은 계단, 벽, 문, 기둥, 낮은 천장과 좁은 통로를 통과한다.
- 공격·회피 Root Motion이 벽에서 멈추고 다음 프레임에 튀지 않는지 확인한다.
- Player와 적이 공격 중 서로의 몸체 안으로 들어가지 않는지 확인한다.
- 점프 정점, 낙하, 경사 착지와 점프 공격을 확인한다.
- Foot IK를 켜고 끌 때 실제 캡슐·HitBox·타격 결과가 같은지 확인한다.
- 사망 애니메이션과 선택 래그돌의 Collider 상태를 확인한다.

### 9.3 Profiler

- 정상 자유 이동과 락온 스트레이프 반복 구간: 관리 힙 `GC Alloc 0 B` 목표
- 공격·회피 Root Motion과 피격 이동: 프레임별 호출 수와 물리 비용
- 지면·벽·IK 물리 질의: 캐릭터당 상한 기록
- 다수 인간형 적과 선택 래그돌: CPU·Physics 비용 비교
