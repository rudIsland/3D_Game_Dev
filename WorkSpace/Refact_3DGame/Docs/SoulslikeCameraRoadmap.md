# 소울류 카메라 로드맵

## 1. 목적과 책임 범위

이 문서는 탐색 자유 시점, 인간형 락온과 NightShade 보스전에서 카메라가 전투 정보를 보여 주면서도 플레이어 입력을 방해하지 않게 만드는 순서를 정의한다.

이 문서가 소유하는 범위는 다음과 같다.

- 마우스 자유 시점과 키보드·마우스 우선 검증
- 카메라 문맥, 거리·FOV·피벗과 문맥 전환
- 자유 공격의 제한적인 소프트 타겟 보정 후보
- 수동 락온 후보 선택·유지·해제·전환
- 카메라 체적 충돌, 거리 축소, 피벗 보정과 선택적 장애물 투명화
- Hit Stop 중 입력·충돌 복구 지속
- 타격 강도에 따른 흔들림·FOV 반응과 중첩 상한
- 현재 크기 또는 약간 큰 NightShade의 보스 구도

캐릭터의 최종 이동·회전은 [SoulslikeCharacterMovementRoadmap.md](SoulslikeCharacterMovementRoadmap.md), 공격 보정 소비와 행동 제한은 [SoulslikeCombatRoadmap.md](SoulslikeCombatRoadmap.md), 전체 마일스톤은 [SoulslikeGameplayRoadmap.md](SoulslikeGameplayRoadmap.md)가 소유한다.

카메라는 행동을 강제로 시작하거나 취소하지 않는다. 카메라가 제공하는 것은 화면 기준 방향, 후보와 구도이며, 전투와 이동 상태가 그 정보를 각자의 제한 안에서 사용한다.

## 2. 목표 카메라 문맥

### 2.1 문맥 종류

| 문맥 | 목적 | 회전 입력 | 대상 처리 | 기본 구도 |
| --- | --- | --- | --- | --- |
| 탐색 자유 시점 | 주변 탐색과 자유 이동 | 마우스가 직접 제어 | 공격 순간 소프트 후보만 제공 | 플레이어 중심 오버숄더/FreeLook |
| 인간형 락온 | 1대1 거리·공격 읽기 | 입력을 허용하되 대상 구도를 제한 보정 | 하나의 수동 대상 유지·전환 | 플레이어와 대상을 함께 보여 주는 중거리 |
| NightShade 보스전 | 긴 창 사거리·벽·페이즈 가독성 | 갑작스러운 강제 회전 금지 | 인간형 단일 락온을 확장한 보스 앵커 | 제한된 거리·FOV·피벗 프로필 |

초거대 보스의 다중 락온 지점, 신체 부위별 카메라와 매우 먼 카메라 거리는 이번 범위에서 제외한다.

### 2.2 문맥 전환

- 전환 직전의 수평·수직 축을 새 문맥에 복사해 화면 방향을 이어 간다.
- 거리·FOV·피벗은 각각 제한 속도와 감쇠로 보간한다.
- 락온 진입이 캐릭터나 카메라를 한 프레임에 대상 정면으로 돌리지 않는다.
- 락온 해제는 현재 구도를 시작점으로 자유 시점에 복귀한다.
- 보스 문맥 진입·해제도 인간형 락온과 같은 축 연속성 규칙을 사용한다.
- 전환 중 장애물 충돌이 발생하면 보기 좋은 보간보다 안전한 충돌 거리를 우선한다.

거리·FOV·피벗 값과 보간 시간은 임의로 고정하지 않는다. 테스트 공간과 실제 전투에서 플레이어·대상·무기 끝이 보이는 범위, 마우스 조작 지연과 멀미 가능성을 측정해 확정한다.

## 3. 입력 → 처리 → 출력 흐름

### 3.1 전체 카메라

```text
마우스 Look 입력
+ 현재 카메라 문맥
+ 플레이어·대상 위치와 상태
+ 원하는 거리·FOV·피벗
→ 문맥별 목표 구도 계산
→ 카메라 체적 충돌 검사
→ 거리 축소
→ 필요하면 피벗 보정
→ 마지막 수단으로 선택적 장애물 투명화
→ 흔들림·FOV 반응을 상한 안에서 합성
→ 최종 카메라 위치·회전·FOV 출력
```

### 3.2 소프트 타겟 보정

```text
공격 요청 시점의 카메라 전방·입력 방향
+ NonAlloc 범위 후보
→ 죽음·거리·화면 각도·가시성 필터
→ 공격 의도와 화면 중심 점수
→ 가장 높은 후보 하나 선택
→ 공격 설정의 최대 보정 각도 안에서 목표 방향 제공
→ 전투 상태가 준비 구간에서만 제한 회전 소비
```

소프트 보정은 락온 상태가 아니다. 카메라가 대상을 계속 추적하거나 실제 타격 구간 중 목표를 다시 선택하지 않는다. 후보가 없거나 보정 각도를 넘으면 원래 카메라/입력 방향으로 공격한다.

### 3.3 수동 락온

```text
락온 입력
→ 후보 수집·중복 Unit 제거
→ 거리·화면 중심·가시성·공격 의도 점수
→ 결정적인 동률 규칙으로 대상 선택
→ TargetLook 문맥과 스트레이프 시작
→ 매 프레임 유지 조건·가림 시간·화면 이탈 검사
→ 사용자 해제 또는 예측 가능한 자동 해제
→ 현재 축을 유지한 FreeLook 복귀
```

후보 선택과 유지 규칙을 분리한다. 진입 시 최고 점수가 매 프레임 조금 바뀐다는 이유로 락온 대상을 자동 교체하지 않는다.

## 4. 후보 수집과 점수

### 4.1 후보 데이터

후보 서비스가 한 Unit마다 제공할 정보는 다음과 같다.

- 대상 Transform과 카메라용 조준 앵커
- 살아 있고 활성 상태인지 여부
- 플레이어와의 수평·실제 거리
- 카메라 전방과 이루는 각도
- 화면 중심으로부터의 거리와 화면 안/밖 여부
- 플레이어 또는 카메라에서 앵커까지의 가시성
- 현재 공격 입력 방향과 이루는 각도
- 후보를 안정적으로 구분하는 ID

한 Unit의 여러 HitBox·Collider가 검색되어도 후보는 하나다. 조준 앵커는 Collider마다 바뀌지 않고 Unit이 제공하며, 없을 때만 몸체 높이를 기준으로 안전하게 대체한다.

### 4.2 선택 점수

선택 점수는 다음 요소를 사용한다.

- 화면 중심 각도: 가장 중요한 기본 요소
- 거리: 같은 화면 각도 안에서 가까운 후보 우선
- 가시성: 완전히 가려진 후보는 제외하거나 큰 감점
- 공격 의도: 소프트 보정에서 이동/공격 방향과 가까운 후보 우선
- 최근 수동 대상: 즉시 재선택 시 작은 안정 보정

가중치는 먼저 테스트 사례를 고정한 뒤 조정한다. 같은 점수에서는 안정 ID 같은 결정적인 기준을 사용하여 프레임·Collider 순서에 따라 대상이 바뀌지 않게 한다.

### 4.3 소프트 보정과 락온 차이

| 항목 | 소프트 보정 | 수동 락온 |
| --- | --- | --- |
| 시작 | 공격 요청과 함께 자동 | 사용자의 명시 입력 |
| 지속 | 공격 시작 방향 결정까지만 | 해제 조건까지 유지 |
| 회전 | 공격별 제한 각도 | 대상 중심 스트레이프와 카메라 보정 |
| 대상 변경 | 실제 타격 구간 중 금지 | 사용자 전환 요청에서만 |
| 실패 | 원래 방향으로 공격 | 자유 시점 유지 또는 복귀 |

## 5. 락온 유지·해제·전환

### 5.1 유지 조건

- 대상이 활성 상태이고 죽지 않았다.
- 최대 유지 거리를 넘지 않았다.
- 화면 이탈과 가림이 각각 허용 시간을 넘지 않았다.
- 카메라가 충돌 복구 중인 짧은 순간은 가림 누적에서 구분한다.
- 플레이어와 대상의 높이 차이가 인간형 카메라 한계를 넘지 않았다.

### 5.2 해제 조건

다음 조건은 예측 가능한 순서로 평가한다.

1. 사용자의 수동 해제
2. 대상 사망·Disable·씬 이탈
3. 최대 거리 초과
4. 지속적인 완전 가림
5. 지속적인 화면 이탈 또는 허용 높이 차이 초과

가림·화면 이탈은 한 프레임으로 해제하지 않는다. 짧은 유예 시간을 두되 실제 전투와 카메라 충돌 측정 후 확정한다. 해제 직전 대상 방향으로 카메라를 급회전하거나 자동으로 다른 대상에 붙이지 않는다.

### 5.3 대상 전환

키보드·마우스 대상 전환 입력은 실제 입력 맵과 조작 테스트 후 확정한다. 전환이 추가되면 다음 규칙을 사용한다.

- 현재 대상 기준 화면 왼쪽·오른쪽 후보만 비교한다.
- 죽음·거리·가시성 필터는 최초 선택과 공유한다.
- 입력 한 번에 한 대상만 넘긴다.
- 후보가 없으면 현재 대상을 유지한다.
- 카메라는 새 대상 방향으로 제한 각속도로 이동한다.

## 6. 카메라 충돌과 가림

### 6.1 처리 순서

카메라 충돌은 다음 순서를 바꾸지 않는다.

1. 문맥이 원하는 피벗·거리·회전으로 이상적인 카메라 위치를 계산한다.
2. 피벗에서 카메라까지 점 Ray가 아닌 카메라 근접면을 대표하는 Sphere/Capsule 체적 검사를 수행한다.
3. 장애물이 있으면 안전 여백을 남기고 카메라 거리를 줄인다.
4. 거리만으로 플레이어와 대상을 볼 수 없을 때 제한 범위에서 피벗을 올리거나 옆으로 보정한다.
5. 그래도 얇은 장애물이 지속적으로 주요 대상을 가릴 때만 선택적으로 투명화한다.

충돌 해결이 락온 대상 회전보다 우선한다. 벽 안에서 목표 구도를 억지로 유지하지 않는다.

### 6.2 복귀

- 장애물이 사라져도 원래 거리로 즉시 튀지 않는다.
- 들어갈 때와 나올 때의 속도를 분리하여 충돌은 빠르게 피하고 복귀는 안정적으로 보간한다.
- 새 장애물이 생기면 복귀 보간을 취소하고 안전 거리로 다시 줄인다.
- 문맥 전환 중에는 새 문맥의 이상 거리로 바로 복귀하지 않고 현재 충돌 거리에서 이어 간다.
- Hit Stop 중에도 충돌 검사와 복귀는 계속 갱신한다.

### 6.3 선택적 장애물 투명화

투명화는 거리 축소와 피벗 보정 뒤의 마지막 수단이다.

- 플레이어·락온 대상과 카메라 사이를 실제로 가리는 Renderer만 대상으로 한다.
- 지형 전체 Material을 복제하지 않는다.
- 가능한 경우 MaterialPropertyBlock 또는 프로젝트 셰이더가 제공하는 교체 가능한 페이드 경계를 사용한다.
- 가림 대상의 진입·유지·복귀 수명을 한 관리자가 소유한다.
- Disable·씬 전환·카메라 문맥 종료에서 원래 상태를 복구한다.
- 셰이더가 페이드를 지원하지 않으면 기능을 생략하고 안전한 거리·피벗 구도를 유지한다.

## 7. NightShade 보스 카메라

NightShade는 현재 인간형 크기를 기본으로 하고 필요하면 약간만 확대한다. 보스 카메라는 인간형 락온의 확장이지 초거대 보스용 별도 시스템이 아니다.

### 7.1 보여야 하는 정보

- Player의 발과 회피 공간
- NightShade의 상체, 창을 든 손과 가능한 범위의 창 끝
- 두 캐릭터 사이 거리와 벽·기둥
- 준비 동작과 페이즈 변화

창 전체를 항상 화면 안에 넣기 위해 카메라를 과도하게 멀리 보내지는 않는다. 빠른 창 끝은 궤적 VFX·Audio와 공격 준비 자세로 보완하고, 실제 조작 거리를 우선한다.

### 7.2 구도 규칙

- 기본 인간형 락온보다 거리·FOV·피벗을 제한 범위에서만 확장한다.
- 보스와 플레이어를 잇는 선, 창 길이와 현재 공간을 사용해 목표 구도를 계산한다.
- 벽 가까이에서는 보스 중심 구도보다 충돌과 플레이어 가독성을 우선한다.
- 페이즈 전환은 짧은 프로필 변화로 표현할 수 있지만 플레이어 마우스 입력을 끊지 않는다.
- 최소 거리 안쪽과 최대 유지 거리 바깥에서 다른 피벗을 사용할 수 있으나 급격한 단계 변화는 금지한다.
- NightShade가 죽거나 지속 가림·거리 초과가 발생하면 인간형과 같은 해제 규칙을 따른다.

## 8. Hit Stop과 카메라 반응

### 8.1 시간 정책

Hit Stop이 공격자와 피해자의 Animator·행동을 멈춰도 다음은 계속 갱신한다.

- 마우스 Look 입력 수집
- 카메라 목표 구도와 충돌 검사
- 안전 거리 축소와 복귀
- 락온 대상의 죽음·Disable 확인
- 카메라 반응 수명과 복구

카메라 갱신은 전투 국소 정지의 영향을 받지 않는 delta time을 사용한다. 전역 `Time.timeScale` 변경에 기대지 않으며, 프로젝트가 일시정지 메뉴를 열었을 때와 Hit Stop을 구분한다.

### 8.2 흔들림과 FOV

- 타격 결과와 강도가 반응 프로필을 선택한다.
- 약한 타격은 작은 위치/회전 흔들림, 강한 타격·패리는 더 큰 반응을 사용할 수 있다.
- `Dodged`와 `Ignored`는 피해 타격 흔들림을 만들지 않는다.
- 여러 결과가 겹치면 진폭·회전·FOV 각각의 합산 상한을 적용한다.
- 새 반응이 이전 반응을 무조건 처음부터 다시 시작하지 않고 우선순위와 남은 강도로 합성한다.
- FOV는 전투 가독성을 해치지 않는 범위에서 원래 문맥 값으로 감쇠 복귀한다.

카메라 반응은 접촉 성공을 재판정하지 않는다. [SoulslikeCombatRoadmap.md](SoulslikeCombatRoadmap.md)가 확정한 결과와 접촉 위치를 입력으로만 사용한다.

### 8.3 확정 타격 결과 입력과 수명

카메라 반응기는 다음 입력만 소비한다.

- `AttackHitResult.Type`
- 반응 강도와 방향
- 접촉점과 Normal
- HurtBox 또는 GuardSurface 종류
- Hit Stop 시간

결과별 기본 의미는 다음과 같다.

| 결과 | 카메라 반응 |
| --- | --- |
| `Ignored`, `Dodged` | 체력 피격 흔들림 없음 |
| `Guarded` | 방패 접촉 방향의 약한 반응 |
| `Parried` | 짧고 선명한 회전·진폭 반응 |
| `Damaged` | 공격 강도에 맞는 기본 반응 |
| `Staggered` | 기본 반응보다 큰 충격, 공통 상한 적용 |
| `GuardBroken`, `KnockedDown` | 전용 프로필, 락온·충돌 규칙은 유지 |
| `Killed` | 사망 문맥이 허용한 마지막 반응 뒤 정리 |

결과 이벤트는 Controller 또는 카메라 반응 생명주기 경계에서 한 번 구독하고 Disable·Destroy·Dispose에서 해제한다. 공격마다 람다를 생성하거나 같은 Detector에 중복 구독하지 않는다. 반응 자산 누락과 풀 고갈은 타격 결과·체력·Stamina를 바꾸지 않는다.

Hit Stop이나 Unit Disable 중 반응이 끝나면 원래 문맥 FOV, 흔들림 가중치와 갱신 상태를 복구한다. 이 복구는 중복 호출에 안전해야 하며 카메라 입력과 충돌 해결은 계속 동작한다.

## 9. 현재 구현에서 보존할 점과 부족한 점

### 9.1 현재 입력 → 처리 → 출력

현재 카메라는 Cinemachine FreeLook 두 개를 자유 시점과 TargetLook에 사용한다. `PlayerTargetCamera`는 두 카메라의 축 값을 복사하고 Priority를 바꾸어 진입·해제 방향을 이어 간다. 락온 중에는 대상 수평 방향으로 X축을, 지정된 세로값으로 Y축을 제한 속도로 이동시킨다.

`PlayerTargetFinder`는 재사용 Collider 배열과 `Physics.OverlapSphereNonAlloc`로 전방 각도·거리 안의 살아 있는 공격 가능 대상을 찾고 가장 가까운 대상을 선택한다. `PlayerTargetLookState`는 수동 입력, 대상 비활성·사망과 최대 거리로 락온을 해제하며 이동을 Target 스트레이프로 바꾼다. 기존 카메라 구현 기록에는 Cinemachine Collider를 통한 장애물 대응이 기록되어 있다.

### 9.2 보존할 기반

- Input Actions와 Cinemachine FreeLook 기반
- 자유 시점과 TargetLook을 분리한 문맥
- 진입·해제 시 축을 복사하는 연속성
- Priority를 사용한 카메라 전환
- NonAlloc 범위 검색과 고정 크기 후보 배열
- 락온 대상의 사망·비활성·거리 해제
- 이동 모드와 카메라 문맥을 같은 시점 상태에서 전환하는 구조

### 9.3 부족한 점

- 후보가 화면 중심보다 가장 가까운 거리 중심으로 선택된다.
- Unit의 여러 Collider 중복 제거, 명시적 조준 앵커와 결정적인 동률 규칙이 없다.
- 가시성·지속 가림·화면 이탈·높이 차이를 선택과 유지에 사용하지 않는다.
- 자유 공격 소프트 보정과 공격 의도 점수가 없다.
- 현재 TargetLook은 대상을 향해 카메라 축을 계속 움직이므로 큰 각도·좁은 공간에서 강제 회전처럼 느껴질 수 있다.
- 충돌을 체적 검사 → 거리 축소 → 피벗 → 투명화 순서와 복귀 속도로 검증한 증거가 없다.
- NightShade 전용 제한 구도, Hit Stop 중 지속 갱신과 흔들림·FOV 중첩 상한이 없다.

현재 구현 비교는 목표를 낮추지 않는다. NonAlloc 검색·축 연속성·문맥 분리를 보존하고 후보·충돌·해제 규칙을 작은 단계로 보완한다.

## 10. 단계별 구현 로드맵

### 카메라 0단계. 구도·입력·충돌 기준선

1. **목표 동작 정의:** 자유·락온·NightShade 문맥의 거리·FOV·피벗·각속도와 테스트 장애물을 측정한다.
2. **입력 → 처리 → 출력:** 고정 마우스·락온 입력과 배치 → 축·위치·FOV·충돌 거리 기록 → 문맥별 기준선 표.
3. **책임 경계와 데이터 소유자:** 측정 도구는 관찰, 카메라 프로필은 목표값, 테스트 Scene은 장애물을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 카메라 리그·Follow·LookAt 참조가 다르면 측정을 섞지 않고 Scene별 미설정을 기록한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 현재 FreeLook/TargetLook 축·Priority 값을 출발점으로 보존하되 최종값으로 단정하지 않는다.
6. **작은 단위의 점진적 전환 순서:** 자유 평지 → 벽·기둥 → 낮은 천장 → 락온 → 해제 → NightShade 거리.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 축 연속성, 최대 회전·거리 변화, 충돌 질의·GC와 키보드·마우스 조작 기준선을 기록한다.

### 카메라 1단계. 자유 시점 체적 충돌과 복귀

1. **목표 동작 정의:** 자유 시점이 벽·기둥·낮은 천장·문에서 클리핑하지 않고 장애물 제거 뒤 부드럽게 복귀한다.
2. **입력 → 처리 → 출력:** 마우스와 이상 카메라 위치 → 체적 Cast·안전 거리·피벗 보정 → 충돌 없는 최종 카메라.
3. **책임 경계와 데이터 소유자:** 리그는 이상 구도, 충돌 해결기는 안전 위치와 복귀 상태를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 공간이 부족하면 거리 축소를 우선하고 복귀 중 새 장애물은 즉시 안전 방향으로 처리한다.
5. **현재 구현에서 보존할 점과 부족한 점:** Cinemachine Collider 기반을 활용하되 체적·피벗·복귀 결과를 명시적으로 검증한다.
6. **작은 단위의 점진적 전환 순서:** 뒤 벽 → 옆 기둥 → 문틀 → 낮은 천장 → 좁은 통로 → 복귀 감쇠.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 카메라 근접면 관통 없음, 복귀 최대 속도, 반복 충돌 `GC Alloc 0 B` 목표와 Cast 수를 확인한다.

### 카메라 2단계. 공통 후보 수집과 점수

1. **목표 동작 정의:** 소프트 보정과 락온이 같은 후보 기반에서 화면 중심·거리·가시성·의도를 일관되게 평가한다.
2. **입력 → 처리 → 출력:** NonAlloc Collider 후보 → Unit 중복 제거·앵커·필터·점수 → 정렬 할당 없는 최고 후보.
3. **책임 경계와 데이터 소유자:** 후보 서비스는 수집·점수, Unit은 앵커·죽음, 전투/카메라는 선택 결과 소비를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 버퍼 초과는 가장 중요한 범위만 평가하고 누락을 계측하며 후보 없음은 정상 결과로 처리한다.
5. **현재 구현에서 보존할 점과 부족한 점:** `OverlapSphereNonAlloc`과 죽음·각도 필터를 유지하고 Unit 중복·화면·가시성·동률 규칙을 추가한다.
6. **작은 단위의 점진적 전환 순서:** 중복 제거 → 화면 각도 → 거리 → 가시성 → 공격 의도 → 동률·버퍼 초과.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 복수 Collider·동률·가림·화면 가장자리 사례와 후보 검색 `GC Alloc 0 B`·가시성 질의 상한을 확인한다.

### 카메라 3단계. 자유 공격 소프트 보정

1. **목표 동작 정의:** 자유 시점 공격이 명확한 근거리 후보로 제한 각도만 보정되고 원하지 않는 대상을 추적하지 않는다.
2. **입력 → 처리 → 출력:** 공격 요청의 카메라·이동 방향 → 후보 점수와 공격별 최대 각도 → 준비 구간용 목표 방향 한 번 제공.
3. **책임 경계와 데이터 소유자:** 후보 서비스는 대상, 전투 설정은 허용 각도, 공격 상태는 제한 회전을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 후보 없음·가림·각도 초과는 원래 방향 유지, 실제 작동 구간에는 재선택·재추적 금지.
5. **현재 구현에서 보존할 점과 부족한 점:** 카메라 수평 전방 공격 방향을 fallback으로 유지하고 선택적 보정만 앞에 추가한다.
6. **작은 단위의 점진적 전환 순서:** 단일 정면 → 화면 가장자리 → 좌우 두 대상 → 가림 → 이동 반대 방향 → 콤보 분기.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 보정 각도 상한, 후보 없는 공격, 콤보 중 방향 고정과 후보 검색 비용을 확인한다.

### 카메라 4단계. 인간형 수동 락온과 스트레이프 구도

1. **목표 동작 정의:** 명시 입력으로 예측 가능한 대상을 고르고 플레이어·적·전투 공간을 보이면서 마우스 조작을 유지한다.
2. **입력 → 처리 → 출력:** 락온 입력과 후보 점수 → 대상 고정·문맥 전환·제한 카메라 축 → Target 스트레이프와 인간형 구도.
3. **책임 경계와 데이터 소유자:** 카메라는 구도, 이동은 스트레이프, 전투는 공격 회전 제한, 시점 상태는 문맥 수명을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 후보 없으면 자유 유지, 수동 해제·사망·거리 초과는 현재 축에서 자유 시점으로 복귀한다.
5. **현재 구현에서 보존할 점과 부족한 점:** FreeLook/TargetLook Priority와 축 복사, 대상 중심 이동을 유지하고 강제 회전 상한을 보완한다.
6. **작은 단위의 점진적 전환 순서:** 진입 → 축 연속성 → 스트레이프 → 마우스 입력 → 해제 → 좌우 전환 → 벽·기둥.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 선택·해제 한 번 처리, 급회전 상한, 이동/카메라 대상 일치와 반복 락온 GC를 확인한다.

### 카메라 5단계. 가림·화면 이탈·거리 해제와 선택적 투명화

1. **목표 동작 정의:** 짧은 가림은 견디고 지속 가림·화면 이탈·거리 초과는 예측 가능하게 해제한다.
2. **입력 → 처리 → 출력:** 대상 상태·가시성·화면 위치·거리 → 유예 타이머와 우선순위 → 유지, 투명화 또는 자유 복귀.
3. **책임 경계와 데이터 소유자:** 락온 유지기는 타이머, 충돌 해결기는 가림 원인, 페이드 관리자는 Renderer 수명을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 한 프레임 가림은 해제하지 않고 페이드 불가 셰이더는 건드리지 않으며 Disable에서 상태를 복구한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 사망·비활성·거리 해제를 유지하고 지속 가림·화면·높이 규칙을 추가한다.
6. **작은 단위의 점진적 전환 순서:** 거리 → 사망 → 화면 이탈 → 얇은 가림 → 두꺼운 가림 → 투명화 → 복귀.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 기둥 통과·벽 뒤 이동·화면 밖·Renderer 복구와 가시성/페이드 GC·질의 상한을 확인한다.

### 카메라 6단계. NightShade 보스 문맥

1. **목표 동작 정의:** 긴 창과 두 캐릭터의 발·공간을 읽을 수 있고 좁은 곳에서도 조작을 빼앗지 않는 구도를 만든다.
2. **입력 → 처리 → 출력:** 보스 앵커·거리·창 방향·공간·페이즈 → 제한 거리·FOV·피벗 프로필 → 충돌 해결된 보스 구도.
3. **책임 경계와 데이터 소유자:** 보스는 앵커·페이즈 정보, 카메라 프로필은 구도, 충돌 해결기는 안전 위치를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 보스 사망·거리·지속 가림은 공통 해제, 좁은 공간은 FOV 확대보다 거리·피벗 안전을 우선한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 인간형 TargetLook 기반을 확장하고 초거대 보스 다중 앵커는 추가하지 않는다.
6. **작은 단위의 점진적 전환 순서:** 현재 크기 → 창 사거리 → 최소 거리 → 벽·기둥 → 페이즈 전환 → 약간 확대 비교.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 창 공격 가독성, 급회전·클리핑 없음, 공통 해제와 보스전 카메라 비용을 확인한다.

### 카메라 7단계. Hit Stop·흔들림·FOV 반응

1. **목표 동작 정의:** 결과 강도가 카메라에 전달되지만 Hit Stop 중에도 Look 입력과 충돌 복구가 계속된다.
2. **입력 → 처리 → 출력:** 확정 타격 결과·강도·접촉 방향 → 반응 프로필·중첩 상한·비정지 delta → 흔들림·FOV와 안전 구도.
3. **책임 경계와 데이터 소유자:** 전투는 결과, 카메라 반응기는 합성과 수명, 문맥은 기본 FOV를 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** `Dodged`·`Ignored`는 피해 반응 없음, Disable·사망·씬 전환에서 반응과 FOV를 복구한다.
5. **현재 구현에서 보존할 점과 부족한 점:** Cinemachine 반응 확장 지점을 사용하되 전역 TimeScale과 무제한 Impulse 중첩을 피한다.
6. **작은 단위의 점진적 전환 순서:** 약한 타격 → 강한 타격 → 가드·패리 → 중첩 → Hit Stop → 문맥 전환 중 반응.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 상한·복구·비정지 갱신, Hit Stop 중 벽 복구와 반응 재생 GC를 확인한다.

### 카메라 8단계. 프레임·좁은 공간·성능 회귀

1. **목표 동작 정의:** 30·60·120 FPS와 모든 테스트 장애물에서 후보·구도·해제·반응이 일관된다.
2. **입력 → 처리 → 출력:** 고정 마우스·락온·전투 입력과 Scene → 축·거리·대상·비용 비교 → 회귀 보고서.
3. **책임 경계와 데이터 소유자:** 자동 테스트는 점수·타이머, PlayMode는 조작·가독성, Profiler는 질의·할당을 소유한다.
4. **실패·중단·충돌·상태 전환 규칙:** 대상 차이·급회전·클리핑·상한 초과가 나오면 관련 단계 완료를 취소한다.
5. **현재 구현에서 보존할 점과 부족한 점:** 고정 배열·캐시·Cinemachine 기반을 유지하며 측정된 병목만 최적화한다.
6. **작은 단위의 점진적 전환 순서:** 자유 충돌 → 후보 → 소프트 → 인간형 락온 → 가림 → NightShade → 반응 → 복합 전투.
7. **자동 테스트·PlayMode·Profiler 완료 조건:** 프레임별 같은 후보·해제, 최대 각속도·거리 오차, 반복 카메라 `GC Alloc 0 B` 목표를 기록한다.

## 11. 검증 기준

### 11.1 자동 테스트

- 여러 Collider를 가진 한 Unit이 후보 하나로 계산됨
- 거리·화면 중심·가시성·공격 의도 점수와 결정적인 동률 처리
- 소프트 보정 최대 각도와 실제 작동 구간 재선택 금지
- 락온 수동 해제, 사망, 거리, 가림, 화면 이탈 우선순위
- 한 프레임 가림 유지와 지속 가림 해제 타이머
- 문맥 전환 축·거리·FOV·피벗 보간 상한
- Hit Stop 중 카메라 갱신과 반응 중첩 상한
- Disable·씬 전환 시 페이드·FOV·반응 복구

### 11.2 Unity PlayMode

- 마우스로 상하좌우를 빠르게 움직여 입력 지연과 강제 회전을 확인한다.
- 벽, 문, 기둥, 낮은 천장, 좁은 통로에서 자유·락온 카메라를 비교한다.
- 정면·화면 가장자리·가려진 복수 대상의 소프트 보정과 락온 선택을 확인한다.
- 대상이 기둥 뒤를 잠깐 지나거나 벽 뒤에 머무를 때 유지·해제를 확인한다.
- 락온 대상 사망·거리 초과·화면 이탈 뒤 현재 구도에서 자유 시점으로 이어지는지 확인한다.
- NightShade의 찌르기·횡베기·최소 거리·페이즈에서 플레이어 발과 전투 공간이 보이는지 확인한다.
- Hit Stop 중 마우스 입력, 벽 충돌 복구와 FOV 복귀를 확인한다.

### 11.3 Profiler

- 후보 검색: 관리 힙 `GC Alloc 0 B` 목표, Collider 버퍼 사용량과 가시성 Ray 수
- 카메라 충돌: 프레임당 Cast 수와 CPU 시간
- 가림 페이드: Material 인스턴스 생성 없음, 활성 Renderer 수
- 흔들림·FOV 합성: 반응 수 상한과 반복 재생 할당
- 인간형/NightShade 전투 전체: 카메라 갱신 비용 비교
